## 一、标签拴在货物上

### PY-02-01 变量与赋值 Variable & Assignment
- **是什么**：变量（variable）是贴在对象上的名字标签，赋值 `=` 把标签拴到对象上。
- **为什么**：痛点：代码里反复出现的值需要一个名字来指代 → 机制：Python 的名字指向对象（引用），不是在内存里"挖坑装值" → 行为：`x = 42` 后 `x` 就代表 42 → 边界：多个名字可指向同一对象（PY-02-11）。
- **怎么写**：
```python
# test_17.py
x = 42          # 对象 42 上贴标签 x
y = x           # y 也贴到同一个对象
print(x, y)
```
→ 运行输出：`42 42`
- **何时用/不用**：凡要复用一个值就起名；一次性的极短表达式不必起名。
- **锚点**：仓库里**标签拴在货箱上**——箱子（对象）不动，标签（名字）可以加一张、换一张；说"x 的货"指的就是那只箱子。
- **易错**：以为 `y = x` 是"复制一份"，之后改 `y` 却连 `x` 一起变（PY-02-13）；赋值 `=` 读作"把右边拴到左边"，不是数学的"等于"。
- **关联**：`→ PY-02-11：id() 能证明两标签拴的是同一只箱子`。

### PY-02-02 命名规则 Naming Rules
- **是什么**：标识符（identifier）只能由字母、数字、下划线组成，不能以数字开头，不能用关键字（keyword）。
- **为什么**：痛点：名字乱起会和语法撞车 → 机制：词法分析器按标识符规则切词，`1bad` 会被当成数字开头的非法字面量 → 行为：非法命名在运行前就报 SyntaxError → 边界：中文变量名合法，但社区惯例用英文（PEP 8：变量小写下划线，常量全大写）。
- **怎么写**：
```python
# test_18.py
name_1 = "合法"
_私有 = "也合法"
print(name_1, _私有)
```
→ 运行输出：`合法 也合法`；反例实测：`'1bad = 1'` → `SyntaxError: invalid decimal literal`，`'class = 1'` → `SyntaxError: invalid syntax`
- **何时用/不用**：起名按"见名知意"；临时循环变量可用 `i/j/k/x`。
- **锚点**：**标签书写规范**——标签第一格不能写数字，也不能写"易燃易爆"这类仓库保留字样（关键字）。
- **易错**：用 `list`、`str`、`id` 当变量名会遮蔽内建函数，之后 `id(x)` 报 `TypeError`；`my-name` 会被解析成减法。
- **关联**：`→ PY-01-16：PEP 8 给出命名风格细则`。

### PY-02-03 动态类型 Dynamic Typing
- **是什么**：变量没有固定类型，对象才有；同一个名字可以先后指向不同类型。
- **为什么**：痛点：写个小脚本还要声明类型太啰嗦 → 机制：赋值只是把标签拴到新对象，类型跟着对象走 → 行为：`x = 1` 后 `x = "s"` 完全合法 → 边界：类型错误推迟到运行时才炸（类型注解与 mypy 可提前查，PY-17）。
- **怎么写**：
```python
# test_19.py
x = 1
print(type(x).__name__)
x = "现在是字符串"
print(type(x).__name__)
```
→ 运行输出：`int` 换行 `str`
- **何时用/不用**：灵活赋值放心用；变量被复用成不同类型是维护噩梦，正式代码宁可起新名。
- **锚点**：同一货位**今天贴"苹果"明天贴"罐头"**——标签随货走，仓库不管你换货。
- **易错**：`x = 1` 后又 `x = "1"`，拼接时才报 `TypeError`，错误离根源很远；变量名重用掩盖真实类型。
- **关联**：`→ PY-02-08：想知道现在是什么货，用 type() 查`；`→ PY-17-01：类型注解给标签写明规格`。

## 二、货架上四种常货

### PY-02-04 int 整数 Integer
- **是什么**：整数类型（int），Python 的整数没有位数上限，随运算自动扩位。
- **为什么**：痛点：其他语言整数超过 2^64 会溢出回绕 → 机制：CPython 用大整数对象存储 → 行为：`2 ** 100` 精确无误 → 边界：算得越精确越慢，普通计数场景无感。
- **怎么写**：
```python
# test_20.py
big = 2 ** 100
print(big)
print(type(big).__name__)
```
→ 运行输出：`1267650600228229401496703205376` 换行 `int`
- **何时用/不用**：计数、索引、精确计算用 int；涉及小数用 float（PY-02-05）或 Decimal（PY-14）。
- **锚点**：**整箱码放的货堆**——想堆多高堆多高，仓库层高（位数）无上限。
- **易错**：`5 / 2` 得 `2.5`（真除法）而不是 `2`，整除要用 `5 // 2`；`1_000_000` 里的下划线只是视觉分隔，会被忽略。
- **关联**：`→ PY-02-05：int 与 float 混算时结果自动升为 float`。

### PY-02-05 float 浮点数 Floating Point
- **是什么**：带小数点的数（float），底层按二进制浮点存储，存在表示误差。
- **为什么**：痛点：`0.1 + 0.2` 看起来该得 0.3 → 机制：0.1 在二进制里是无限循环小数，只能近似存 → 行为：累加出现 `0.30000000000000004` 这类尾巴 → 边界：比较用 `math.isclose` 或先 round，钱款计算别用 float。
- **怎么写**：
```python
# test_21.py
print(0.1 + 0.2)
print(round(0.1 + 0.2, 10))
print(0.1 + 0.2 == 0.3)
```
→ 运行输出：`0.30000000000000004` / `0.3` / `False`
- **何时用/不用**：测量值、统计、科学计算用 float；金额、精确小数用 Decimal 或"按分存整数"。
- **锚点**：**散装称重货**——电子秤永远差那么一粒米，别拿秤称出的数去对账本（精确比较）。
- **易错**：`float("nan") == float("nan")` 是 `False`；`round()` 是"银行家舍入"，`round(2.5)` 得 `2`。
- **关联**：`→ PY-02-09：float() 把字符串货换成散装货`。

### PY-02-06 bool 布尔值 Boolean
- **是什么**：只有 `True` / `False` 两个值的类型（bool），表示"是/否"。
- **为什么**：痛点：分支判断需要一个明确的开关量 → 机制：比较运算产生 bool；bool 是 int 的子类（True 即 1）→ 行为：可直接参与算术与条件判断 → 边界：`isinstance(True, int)` 为 True 属历史设计，别拿 True 当数字写业务代码。
- **怎么写**：
```python
# test_22.py
print(isinstance(True, bool), isinstance(True, int))
print(True + True)
```
→ 运行输出：`True True` / `2`
- **何时用/不用**：条件、标志位用 bool；别用 `1/0`、`"yes"/""` 代替 True/False。
- **锚点**：货架上的**指示灯**——亮（True）灭（False）一目了然；灯泡拧下来一量，居然也通 1 号电池的电（bool 是 int 子类）。
- **易错**：写 `if x = True:` 会 SyntaxError（`=` 是赋值）；`True == 1` 为 True 会让"开关灯"和"数一个"混在一起。
- **关联**：`→ PY-02-07：0、""、None 等假值在条件里等价于 False`；`→ PY-05-06：真值测试的完整清单`。

### PY-02-07 None 空对象 NoneType
- **是什么**：`None` 是"没有值"的专属对象，类型叫 `NoneType`，全解释器只有一个。
- **为什么**：痛点：函数"没东西可返回"、变量"还没填"需要一个明确占位 → 机制：None 是单例对象（singleton），用 `is` 判断 → 行为：未写 return 的函数默认返回 None → 边界：None 不等于 0、""、False，虽然在条件判断里都算"假"。
- **怎么写**：
```python
# test_23.py
x = None
print(x is None)
print(type(None).__name__)
```
→ 运行输出：`True` / `NoneType`
- **何时用/不用**：表示"空/无"用 None；空列表用 `[]`（有容器但没货）。
- **锚点**：**空货架位**上放一块"暂无货物"牌——牌本身是确切的东西（None 是对象），不是"货架消失"。
- **易错**：用 `x == None` 判断（PEP 8 要求 `x is None`）；把 None 当 0 参与运算直接 `TypeError`。
- **关联**：`→ PY-02-12：is 判断的正是"是不是同一只箱子"，对 None 用它最稳`。

## 三、验货与换包装

### PY-02-08 type() 与 isinstance()
- **是什么**：`type(obj)` 返回对象的类型；`isinstance(obj, 类型)` 判断对象是否属于该类型（含子类）。
- **为什么**：痛点：动态类型下不知道手里的货是什么品类 → 机制：类型信息存在对象头上，两个内建函数各取所需 → 行为：type 精确、isinstance 认子类 → 边界：多类型判断写元组 `isinstance(x, (int, float))`。
- **怎么写**：
```python
# test_24.py
print(type(3.14).__name__)
print(isinstance(3.14, (int, float)))
```
→ 运行输出：`float` / `True`
- **何时用/不用**：类型分派、调试用 isinstance；日常代码优先"鸭子类型"（有啥方法用啥），见 PY-10 协议。
- **锚点**：`type` 是**看标签写的品类**，`isinstance` 是**验货员拿品类单核对**——验货员认父子关系（子类也算）。
- **易错**：`type(x) == int` 不认 bool/int 子类关系；用 isinstance 做过度的类型检查会把灵活的 Python 写成笨重的 Java。
- **关联**：`→ PY-02-06：isinstance(True, int) 为 True 正是子类关系`；`→ PY-09-04：继承让 isinstance 的子类判断有意义`。

### PY-02-09 类型转换 Type Conversion
- **是什么**：`int()`、`float()`、`str()` 等把对象转成目标类型（conversion）。
- **为什么**：痛点：input()、读文件拿到的都是字符串，直接算术会炸 → 机制：类型构造函数按规则生成新对象 → 行为：`int("42")` 得 42，`str(42)` 得 "42" → 边界：转不过去就抛 ValueError（如 `int("3.9")`）。
- **怎么写**：
```python
# test_25.py
print(int("42") + 8)
print(float("3.5") * 2)
print(str(42) + "岁")
print(int(3.9))
```
→ 运行输出：`50` / `7.0` / `42岁` / `3`；反例实测：`int("3.9")` → `ValueError: invalid literal for int() with base 10: '3.9'`
- **何时用/不用**：拿到外部文本要计算时必转；同类型间不必转。
- **锚点**：**换包装重新贴标**——散装糖果（3.9）装进"整箱"包装（int）只能装 3 颗；"3.9"这种贴着小数标签的货，硬塞整箱包装机当场罢工（ValueError）。
- **易错**：`int(3.9)` 是截断不是四舍五入（得 3）；`int("3.9")` 报错，要先 `float()` 再 `int()`。
- **关联**：`→ PY-02-10：最常见的转换来源就是 input()`；`→ PY-03-14：str 与 bytes 的转换走 encode/decode`。

### PY-02-10 input() 只返回字符串
- **是什么**：`input(提示语)` 暂停程序读取一行用户输入，永远返回 `str`。
- **为什么**：痛点：程序要和人交互拿数据 → 机制：键盘输入天然是一串字符 → 行为：`input()` 的结果可直接拼接，但不能直接参与算术 → 边界：要数字必须显式转换（PY-02-09），转换失败抛 ValueError。
- **怎么写**：
```python
# test_32.py
age = input()              # 喂入 21
print(type(age).__name__)
print(int(age) + 1)        # 算术前先转 int
```
→ 运行输出（实测，喂入 21）：`str` / `22`；`age + 1` 的真实报错见下「易错」
- **何时用/不用**：命令行交互用；自动化脚本用参数/文件拿数据更稳（PY-15）。
- **锚点**：客户**手写订单单**——订单永远是手写体纸条（字符串），要录进库存系统得先抄成数字。
- **易错**：`input() + 1` 报 `TypeError: can only concatenate str (not "int") to str`；用户敲个空格也会得到 `" "`，记得 `strip()`（PY-03-06）。
- **关联**：`→ PY-02-09：str→int 的转换坑就在这一步`。

## 四、条码与封装

### PY-02-11 id() 与对象身份 Identity
- **是什么**：`id(obj)` 返回对象在内存中的唯一编号（生命周期内不变），可用来判断"是不是同一个对象"。
- **为什么**：痛点：两个变量值相同，分不清是同一箱货还是两箱一样的货 → 机制：每个对象创建时分配唯一 id → 行为：`id(a) == id(b)` 即两者引用同一对象 → 边界：对象销毁后 id 可能被复用，别跨时间比较。
- **怎么写**：
```python
# test_26.py
a = [1, 2]
b = a
print(id(a) == id(b))
b.append(3)
print(a)
```
→ 运行输出：`True` 换行 `[1, 2, 3]`
- **何时用/不用**：教学演示、排查"为什么改一处动全身"时用；业务代码用 `is` 表达意图更清晰。
- **锚点**：货箱上的**条码**——两标签扫出同一个条码，说明是同一只箱子；改 b 箱内容 a 箱跟着变，因为本来就是一只箱子。
- **易错**：以为 `b = a` 复制了列表；打印 id 的十进制数字去比较含义，其实只需关心相等与否。
- **关联**：`→ PY-02-13：可变对象共用条码时的连带修改`；`→ PY-19-02：深浅拷贝的系统对比`。

### PY-02-12 is 与 == 的分工
- **是什么**：`is` 比较身份（同一对象吗），`==` 比较值（内容相等吗）。
- **为什么**：痛点：`x == y` 为 True 时两者仍可能是两个独立对象 → 机制：`==` 默认走 `__eq__` 比内容，`is` 比 id（PY-10 魔术方法）→ 行为：值相等未必身份相等 → 边界：小整数与短字符串被 CPython 缓存，`is` 偶然为 True，不能当规律用。
- **怎么写**：
```python
# test_27.py
x = int("257")
y = int("257")
print(x == y, x is y)
print(x is not y)
```
→ 运行输出：`True False` / `True`
- **何时用/不用**：比较值用 `==`；判断 None/True/False 或单例用 `is`。
- **锚点**：`==` 比**两箱货的内容**，`is` 比**条码**——内容一样（True False）不代表是同一只箱子。
- **易错**：`a is 257` 这类写法在 3.8+ 起 `SyntaxWarning`；用 `is` 比较字符串/数字是未定义行为（缓存是实现细节）。
- **关联**：`→ PY-02-11：id() 是 is 的底层依据`；`→ PY-10-04：== 背后是 __eq__ 魔术方法`。

### PY-02-13 可变与不可变 Mutable vs Immutable
- **是什么**：不可变对象（int、float、str、tuple）创建后内容不能改；可变对象（list、dict、set）可原地修改。
- **为什么**：痛点：改一个变量，另一个跟着变，很"闹鬼" → 机制：可变对象原地改，id 不变、所有引用者都看到新内容；不可变对象的"改"其实是造新对象、重贴标签 → 行为：字符串拼接产生新对象，列表 append 改老对象 → 边界：可变对象当函数默认参数是经典雷（PY-07）。
- **怎么写**：
```python
# test_28.py
s = "ab"
s_before = id(s)
s = s + "c"
print(id(s) == s_before)
lst = [1, 2]
lst_before = id(lst)
lst.append(3)
print(id(lst) == lst_before, lst)
```
→ 运行输出：`False` / `True [1, 2, 3]`
- **何时用/不用**：需要稳定键/字典键用不可变；需要攒数据用可变。
- **锚点**：**可开箱的纸箱**（list：贴着封条也能拆开增删货品）vs **出厂封死的罐头**（str/int：想改只能开一罐新的，旧罐原样）。
- **易错**：`t = ([1], [2])` 元组本身不可变，但里面的列表照样能改；把可变对象存进集合/dict 当键直接 `TypeError`。
- **关联**：`→ PY-02-11：改前改后 id 是否不变，是判断可变性的试金石`；`→ PY-04-10：容器的深浅拷贝`。

## 五、仓库作业习惯

### PY-02-14 链式赋值与多重赋值
- **是什么**：`a = b = 0` 一次给多个名字拴标签；`a, b = 1, 2` 多重赋值；`a, b = b, a` 完成交换。
- **为什么**：痛点：交换两值需要临时变量，啰嗦易错 → 机制：右边先打包成元组（tuple），再整体解包给左边 → 行为：一行完成多变量初始化与交换 → 边界：左右个数不等会抛 ValueError。
- **怎么写**：
```python
# test_29.py
a = b = 0
a, b = 1, 2
a, b = b, a
print(a, b)
```
→ 运行输出：`2 1`
- **何时用/不用**：交换、拆包返回值必用；`a = b = []` 这种链式拴可变货要小心（两标签同箱）。
- **锚点**：**同一批货挂多张相同标签**（链式）；**两个货位整箱互换**（交换）——打包、贴签、拆包一气呵成。
- **易错**：`x = y = []` 后 append 会互相干扰（同一只箱子）；`a, b = [1, 2, 3]` 报 `ValueError: too many values to unpack`。
- **关联**：`→ PY-02-13：链式拴可变货的连带效应`；`→ PY-04-11：解包的完整玩法`。

### PY-02-15 常量约定 Constants Convention
- **是什么**：Python 没有常量关键字，约定全大写下划线命名表示"不应修改"（constant）。
- **为什么**：痛点：魔法数字散落各处，改一处漏三处 → 机制：模块顶部集中定义名字，语言不强制但团队靠约定与 code review 保障 → 行为：`MAX_RETRY = 3` 全库引用同一处 → 边界：真去改它语言不拦，只有 linter 会警告。
- **怎么写**：
```python
# test_30.py
MAX_RETRY = 3       # 语言不强制，靠约定
PI = 3.14159
print(MAX_RETRY, PI)
```
→ 运行输出：`3 3.14159`
- **何时用/不用**：出现两次以上的固定值都值得命名；一次性临时值不必。
- **锚点**：仓库的**封条区**——全大写就是贴了封条的固定货位（MAX_RETRY），谁都别动；封条防君子不防小人（语言不强制）。
- **易错**：`PI` 之后又 `pi = 3.14` 两种写法并存，改一个漏一个；把可变对象（如列表）当"常量"照样会被改。
- **关联**：`→ PY-20-03：配置管理把常量移出代码`。

### PY-02-16 f-string 基础 f-String
- **是什么**：f-string（formatted string literal）是在引号前加 `f`，用 `{}` 直接嵌入表达式的字符串。
- **为什么**：痛点：拼接字符串要满屏加号与 str() 转换 → 机制：运行时求值 `{}` 内表达式并格式化进文本 → 行为：`f"{name} 明年 {age+1} 岁"` 一步到位 → 边界：复杂格式规格（宽度、精度）见 PY-03-10；3.12 以前嵌套同引号需换引号。
- **怎么写**：
```python
# test_31.py
name, age = "小明", 18
print(f"{name} 明年 {age + 1} 岁")
```
→ 运行输出：`小明 明年 19 岁`
- **何时用/不用**：一切字符串插值优先 f-string；老代码里的 `%` 与 `.format()` 会读即可（PY-03-11/12）。
- **锚点**：**出库单模板自动打印**——空白出库单上留着 `{}` 卡槽，机器当场把当前货名数量打进去。
- **易错**：外层内层都用双引号导致截断（外 `f"..."` 内用 `'...'`）；`{}` 里忘写变量名报 `NameError`。
- **关联**：`→ PY-03-10：格式控制符（:.2f、:>8）接在表达式后面`。

## ✅ 自测清单（合上本篇，先写再看）

1. 写出一段代码，证明 `b = a` 之后改 `b` 会影响 `a`（提示：id 与 append）。
> 答案：`a = [1]; b = a; b.append(2); print(a)` → `[1, 2]`，且 `id(a) == id(b)` 为 `True`。
2. `x = int("257"); y = int("257")`，`x == y` 与 `x is y` 各是什么？为什么？
> 答案：`True`、`False`：值相等但两次构造出两个对象；257 超出小整数缓存范围。
3. 为什么 `0.1 + 0.2 == 0.3` 是 `False`？正确比较姿势是什么？
> 答案：0.1 二进制只能近似存储，累加出 `0.30000000000000004`；用 `math.isclose` 或 `round(a-b, 10) == 0`。
4. `input("年龄: ")` 拿到 `21` 后直接 `+1` 报什么错？给出两条正确写法之一。
> 答案：`TypeError: can only concatenate str (not "int") to str`；`int(input(...)) + 1` 或先 `age = int(input(...))`。
5. 判断"变量是不是没值"应该写 `x == None` 还是 `x is None`？
> 答案：`x is None`——None 是单例，`is` 比身份最稳，也是 PEP 8 规定写法。
