## 一、列表·货架区（口号：增删改查四件套）

### PY-04-01 列表创建与索引切片 List: Index & Slice
- **是什么**：列表（list）是有序、可变的序列容器；索引（index）取单件，切片（slice）取一段。
- **为什么**：驿站几百件货一件一个变量就没法管理 → 列表按顺序占位存件，位置即下标 → 支持负索引从尾部数、切片取区间 → 单件越界报错，切片越界却静默截断。
- **怎么写**：
```python
shelf = ["包裹A", "包裹B", "包裹C", "包裹D"]
print(shelf[0], shelf[-1], shelf[1:3], shelf[::-1])
print(len(shelf), "包裹A" in shelf, shelf[10:20])   # 切片越界不报错
```
→ 运行输出：`包裹A 包裹D ['包裹B', '包裹C'] ['包裹D', '包裹C', '包裹B', '包裹A'] ⏎ 4 True []`
- **何时用/不用**：要顺序、要按下标/切片就用列表；只做"在不在"判断用 set 更快。
- **锚点**：货架每格贴货位号标签，从驿站门口往回数的标签是负数——负索引=门口回头数货位。
- **易错**：`shelf[10]` 抛 IndexError，`shelf[10:20]` 只是返回 `[]` 不报错；`[::-1]` 生成新列表，原货架不动。
- **关联**：`→ PY-04-04：改标签、点件数都发生在这排货架` ｜ `→ PY-04-16：货架重排号用 sort`。

### PY-04-02 增：append / extend / insert
- **是什么**：列表三种"上架"动作——append 加一件、extend 一批逐件上、insert 插到指定货位。
- **为什么**：到货形态不同（单件/整批/加急插队）→ 一个方法包办不了 → 三种方法各管一种形态 → append 传列表会把整批当"一件"套进去。
- **怎么写**：
```python
shelf = ["包裹A"]
shelf.append("包裹B")                                # 尾部加一件
shelf.extend(["包裹C"]); shelf.insert(0, "加急件")   # 整批上架 / 插队
print(shelf)
```
→ 运行输出：`['加急件', '包裹A', '包裹B', '包裹C']`
- **何时用/不用**：单件 append、批量 extend、插队 insert；只是"合并成新列表"用 `+` 更直观（不改原列表）。
- **锚点**：加急件插到货架最前头，整批货由分拣带一次性推上架——上架三招：单件尾放、整排推、加急插队。
- **易错**：`bad.append(["B", "C"])` 后 `len` 只 +1（嵌套一层，实测 `['包裹A', ['包裹B', '包裹C']]`）；extend(字符串) 会按字符逐个拆开上架。
- **关联**：`→ PY-04-03：上架与下架对称` ｜ `→ PY-04-15：批量上架与解包是一对`。

### PY-04-03 删：pop / remove / del / clear
- **是什么**：四种"下架"动作——pop 按货位取走、remove 按面单值删第一件、del 按位置/切片撕货位、clear 清空整排。
- **为什么**：取件场景不同（按位取/按值取/批量清）→ 方法按"定位方式"分工 → pop 用下标且返回被取值，remove 不返回且只删第一个匹配 → 不存在时分别抛 IndexError/ValueError。
- **怎么写**：
```python
shelf = ["加急件", "包裹A", "包裹B", "加急件"]
print(shelf.pop(), shelf.pop(0))       # pop 靠货位（末件 / 0 号位）
shelf.remove("包裹B"); del shelf[:]    # remove 靠面单 / del 按位切片
print(shelf)
```
→ 运行输出：`加急件 加急件 ⏎ []`
- **何时用/不用**：要"取走并用"选 pop；只删第一个匹配选 remove；删一段用 del 切片；全部清空用 clear。
- **锚点**：pop 是按货位号取件，remove 是拿面单满货架找第一件——"pop 靠位、remove 靠面单"。
- **易错**：remove 只删第一个匹配；`shelf.remove("包裹Z")` 实测抛 `ValueError: list.remove(x): x not in list`；`pop()` 无参删的是末件不是 0 号位。
- **关联**：`→ PY-04-04：改查同货架` ｜ `→ PY-12 异常：IndexError/ValueError 的处理`。

### PY-04-04 改与查：赋值、in、count / index
- **是什么**：改=按下标换标签（`shelf[1] = x`）；查=点件数 count、找货位 index、问在不在 in。
- **为什么**：改地址/换标签必须按下标就地改，查件要给客户明确答案（几件、第几格、有没有）→ 四个动作覆盖"改查"闭环 → index 找不到抛 ValueError，count 安静返回整数。
- **怎么写**：
```python
shelf = ["包裹A", "包裹B", "包裹C"]
shelf[1] = "改址件"                                        # 按货位改标签
print(shelf, shelf.count("包裹C"), shelf.index("包裹C"), "包裹A" in shelf)
```
→ 运行输出：`['包裹A', '改址件', '包裹C'] 1 2 True`
- **何时用/不用**：只问"在不在"用 in（不抛异常）；要位置用 index 前最好先 `if x in lst` 或套 try。
- **锚点**：换货位标签（改）与拿扫码枪点数（查）——驿站每天盘库就这两件事。
- **易错**：index 只找第一个匹配，找不到实测抛 `ValueError: '包裹Z' is not in list`；count 对不存在的值返回 0，别拿它当存在性检查再取 index。
- **关联**：`→ PY-04-01：下标体系` ｜ `→ PY-05-10：in 是成员运算符`。

## 二、元组·塑封面单（口号：贴上就不改）

### PY-04-05 元组 tuple：不可变、逗号坑与用途
- **是什么**：元组（tuple）是有序、**不可变**序列；单元素元组必须带尾逗号；常作字典键、多值信封。
- **为什么**：面单一旦塑封就不能涂改，改了就失去凭证效力 → tuple 锁死元素槽位，写操作当场抛 TypeError → 于是可哈希、能当字典键 → 但 `(x)` 与数学括号冲突，Python 只认"逗号才是元组"。
- **怎么写**：
```python
waybill = ("SF001", "北京", 1.5)                  # 面单三元组
print(waybill[0], type(("SF001")).__name__, type(("SF001",)).__name__)
try:
    waybill[0] = "SF002"                          # 塑封：写不上去
except TypeError as e:
    print("TypeError:", e)
```
→ 运行输出：`SF001 str tuple ⏎ TypeError: 'tuple' object does not support item assignment`
- **何时用/不用**：数据不该变（坐标、记录行、字典键、多返回值）用 tuple；要增删改用 list。
- **锚点**：塑封面单 + 尾逗号骑缝章——纸能看（读索引）但笔写不上去；盖了逗号章才算元组。
- **易错**："不可变"只锁槽位：`box = ("SF002", ["文件"]); box[1].append("发票")` 后 box 变 `('SF002', ['文件', '发票'])`；`{("SF001","A-01"): "已上架"}` 能作键正因不可变。
- **关联**：`→ PY-04-08：可哈希才能作字典键` ｜ `→ PY-04-15：元组是解包的常用源`。

## 三、字典·取件码柜（口号：报码开柜）

### PY-04-06 字典创建与取值 dict: [] 与 get
- **是什么**：字典（dict）是键（key）→ 值（value）映射容器；`d[k]` 直取，`get(k, default)` 带兜底。
- **为什么**：几百个柜格靠"取件码"找包裹，比按位置扫货架快得多 → dict 用哈希把键直接算成柜位 → 码不存在时 `[]` 抛 KeyError，get 返回默认值 → "缺键是否预期内"决定用哪个。
- **怎么写**：
```python
locker = {"SF001": "A-01", "SF002": "B-03"}
print(locker["SF001"], locker.get("SF003", "无此码"), locker.get("SF003"))
try:
    locker["SF003"]                       # [] 缺键就报警
except KeyError as e:
    print("KeyError:", e)
```
→ 运行输出：`A-01 无此码 None ⏎ KeyError: 'SF003'`
- **何时用/不用**：查得到是常态用 `[]`（错了早点炸）；查不到是常态用 get；只是问在不在用 `k in d`。
- **锚点**：客户报取件码，柜子"嘀"一声开柜；报错码时要么报警（KeyError）要么说"无此码"（get 默认值）。
- **易错**：get 缺省返回 None，会把"没这个键"和"值就是 None"混为一谈——重要区分用 `in` 或 get 的哨兵默认值。
- **关联**：`→ PY-04-07：增删改` ｜ `→ PY-04-11：frozenset 才能当键`。

### PY-04-07 字典增删改：= / update / pop / del
- **是什么**：`d[k] = v` 新键新增、旧键修改；update 批量并入；pop 取走并返回；del 直接销柜。
- **为什么**：开新柜、换柜、批量登记、销柜是驿站日常 → 四个动作一一对应 → pop 带默认值不抛异常，del 缺键抛 KeyError → "取走还要用"选 pop，"只要它消失"选 del。
- **怎么写**：
```python
locker = {"SF001": "A-01"}
locker["SF002"] = "B-03"; locker.update({"SF003": "C-01"})   # 新增 / 批量并入
locker["SF001"] = "A-02"; print(locker)                        # 已有键 = 修改
print(locker.pop("SF002"), locker.pop("SF999", "无此码"))      # 取走（带兜底）
del locker["SF003"]; print(locker)
```
→ 运行输出：`{'SF001': 'A-02', 'SF002': 'B-03', 'SF003': 'C-01'} ⏎ B-03 无此码 ⏎ {'SF001': 'A-02'}`
- **何时用/不用**：单键单值用 `[]`；合并两个字典用 update 或 `|`（3.9+，生成新字典）；想安全取走用 `pop(k, None)`。
- **锚点**：柜台三块牌子：开新柜（=）、批量登记（update）、销柜（pop/del）。
- **易错**：遍历字典的同时增删键会抛 RuntimeError（迭代中字典大小变了）。
- **关联**：`→ PY-04-08：遍历` ｜ `→ PY-04-15：pop 的返回值可直接解包`。

### PY-04-08 字典遍历、顺序与嵌套
- **是什么**：keys/values/items 三种视图（码条/包裹/成对）；3.7+ 字典**保持插入顺序**；值任意 → 可嵌套字典。
- **为什么**：盘库既要"全部单号"也要"单号-柜位对照"→ 三个视图按需取 → 3.7 起底层保证插入序，`list(d)` 就是登记先后 → 但键必须可哈希，列表作键当场 TypeError。
- **怎么写**：
```python
locker = {"SF003": "A-03", "SF001": "A-01"}     # 3.7+ 保持插入顺序
locker["SF002"] = "A-02"
print(list(locker.keys()), list(locker.values()))
for code, box in locker.items(): print(code, "->", box)   # 成对取
print("SF001" in locker, "A-01" in locker)                # in 只查键
print({"网点1": {"A区": ["包裹A"]}}["网点1"]["A区"][0])     # 嵌套：层层报码
```
→ 运行输出：`['SF003', 'SF001', 'SF002'] ['A-03', 'A-01', 'A-02'] ⏎ SF003 -> A-03 ⏎ SF001 -> A-01 ⏎ SF002 -> A-02 ⏎ True False ⏎ 包裹A`
- **何时用/不用**：只要键就 `for k in d`；要成对用 items；要按键排序请显式 `sorted(d)`，别把插入序当排序结果。
- **锚点**：柜旁三张清单 + 按开柜先后贴号码牌的分区图，柜中还能套小柜（嵌套）。
- **易错**：`in` 只查键不查值（`"A-01" in locker` 是 False）；`{[1, 2]: "A-01"}` 实测抛 `TypeError: unhashable type: 'list'`；`{}` 是空字典不是空集合。
- **关联**：`→ PY-04-05：键的可哈希要求` ｜ `→ PY-04-13：items 是字典推导式的原料`。

## 四、集合·安检口（口号：重复件拒收）

### PY-04-09 集合 set：去重与增删
- **是什么**：集合（set）是**无序、不重复**、元素可哈希的容器；`set()` 去重，add 增、discard 删（不报错）、remove 删（报错）。
- **为什么**：重复单号会造成重复派件 → 安检口自动拒收重复件 → 哈希去重带来 O(1) 查找 → 代价是无序、元素必须可哈希。
- **怎么写**：
```python
codes = ["SF001", "SF002", "SF001", "SF003"]
uniq = set(codes)                                     # 去重
uniq.add("SF004"); uniq.discard("SF999")              # discard 不报错
print(sorted(uniq), len(uniq))
```
→ 运行输出：`['SF001', 'SF002', 'SF003', 'SF004'] 4`
- **何时用/不用**：去重、高频成员判断用 set；要顺序用 list，要键值用 dict。
- **锚点**：安检口的去重传送带——同一单号第二次经过，机器直接滑进回收箱。
- **易错**：set 无序（展示前要 `sorted()`）；discard 安静、remove 抛 `KeyError: 'SF999'`，语义别混。
- **关联**：`→ PY-04-10：集合运算` ｜ `→ PY-05-10：in 在 set 上是 O(1)`。

### PY-04-10 集合运算：并 / 交 / 差 / 对称差
- **是什么**：`|` 并集、`&` 交集、`-` 差集、`^` 对称差，另有 `<=` 子集判断；都返回新集合。
- **为什么**：两网点对账要知道"都到了/只在 A/差哪些件"→ 集合代数一一对应 → 运算不改原集合 → 差集有方向，`a-b ≠ b-a`。
- **怎么写**：
```python
a, b = {"SF001", "SF002"}, {"SF002", "SF003"}
print(sorted(a | b), sorted(a & b), sorted(a - b), sorted(a ^ b))
print(a <= b, a <= {"SF001", "SF002", "SF003"})   # 子集判断
```
→ 运行输出：`['SF001', 'SF002', 'SF003'] ['SF002'] ['SF001'] ['SF001', 'SF003'] ⏎ False True`
- **何时用/不用**：名单对比、去重合并、差异排查用集合运算；要保留重复记录别用 set。
- **锚点**：两个安检筐倒出来对账：并=全部摊开，交=两边都有的件，差=A 筐独有的件。
- **易错**：`-` 方向别写反；`set | list` 抛 TypeError（两侧都得是集合）。
- **关联**：`→ PY-04-09：集合本体` ｜ `→ PY-05-11：& | ^ 与位运算同形不同义`。

### PY-04-11 frozenset：封膜的安检筐
- **是什么**：frozenset 是不可变集合：可哈希、可作字典键，但没有 add/remove。
- **为什么**：普通 set 会变、哈希值跟着变，没法当键 → frozenset 封膜后哈希稳定 → 可作 dict 键、可当另一个 set 的元素 → 代价是完全只读。
- **怎么写**：
```python
frozen = frozenset(["SF001", "SF002"])
print({frozen: "A区"}[frozen], len(frozen), hasattr(frozen, "add"))
```
→ 运行输出：`A区 2 False`
- **何时用/不用**：集合要当键/当元素时用 frozenset；否则普通 set 足够。
- **锚点**：封膜的安检筐——筐里件看得见（可迭代），塑封后一件也塞不进。
- **易错**：`frozen.add("x")` 实测抛 `AttributeError: 'frozenset' object has no attribute 'add'`；里面仍只能放可哈希元素。
- **关联**：`→ PY-04-05：不可变→可哈希同一条链` ｜ `→ PY-04-08：字典键的要求`。

## 五、推导式·分拣打包带（口号：先结果后循环）

### PY-04-12 列表推导式 List Comprehension
- **是什么**：`[结果 for 变量 in 可迭代 if 条件]` 一行生成新列表。
- **为什么**："筛出重件并加倍标重"这类映射+过滤用 append 循环要 4 行 → 推导式把"结果在前、来源居中、条件收尾"压成一行 → 内部走 C 层循环略快于手写 append → 嵌套超过一层就该退回普通循环。
- **怎么写**：
```python
weights = [1.2, 3.5, 0.8, 2.0]
heavy = [w for w in weights if w >= 1.0]     # 结果在前、for 居中、if 收尾
print(heavy, [w * 2 for w in weights])
```
→ 运行输出：`[1.2, 3.5, 2.0] [2.4, 7.0, 1.6, 4.0]`
- **何时用/不用**：一行说得清的"变换/筛选"用推导式；有复杂分支、多层嵌套、要副作用（print）就写 for。
- **锚点**：分拣打包带——包裹逐个过带被筛选、贴新面单，出带时排成一列；"推"字就是推着件过带。
- **易错**：循环变量会泄漏到外层（推导式后 `w` 还在，值是最后一个）；别在推导式里塞副作用。
- **关联**：`→ PY-04-13：字典推导式` ｜ `→ PY-11 迭代器：小括号 `(x for x in ...)` 是惰性的生成器表达式`。

### PY-04-13 字典推导式 Dict Comprehension
- **是什么**：`{键: 值 for ... in ... if ...}` 一行生成新字典。
- **为什么**：给一批单号批量配柜位、或从大字典筛出子集，手写循环要逐条赋值 → 推导式把"键值对构造"和"遍历筛选"压成一行 → 键重复时后者静默覆盖前者 → 只适合"构造规则一句话说得清"的场景。
- **怎么写**：
```python
codes = ["SF001", "SF002", "SF003"]
locker = {code: f"A-0{i}" for i, code in enumerate(codes, 1)}   # 码 → 柜
print(locker, {k: v for k, v in locker.items() if k != "SF002"})
```
→ 运行输出：`{'SF001': 'A-01', 'SF002': 'A-02', 'SF003': 'A-03'} {'SF001': 'A-01', 'SF003': 'A-03'}`
- **何时用/不用**：键值构造规则单一（反转、筛选、改值）用它；仅 2~3 个键时直接写字面量更清晰。
- **锚点**：快递柜批量开柜贴码：一排柜门"左贴取件码、右写柜位号"，机器一路贴过去。
- **易错**：源数据键重复时最后一个值胜出（前面的被覆盖且无提示）。
- **关联**：`→ PY-04-12：结构同源` ｜ `→ PY-04-08：items() 是常用原料`。

### PY-04-14 集合推导式与嵌套边界
- **是什么**：`{结果 for ... in ...}` 生成集合（自动去重）；推导式可嵌套，**外层 for 在前、内层在后**。
- **为什么**：既要变换又要去重，"推导式+集合"一步到位 → 嵌套时书写顺序与嵌套 for 一致（从外到内）→ 但两层以上可读性骤降 → 边界：超过一层就拆普通循环。
- **怎么写**：
```python
grid = [["包裹A", "包裹B"], ["包裹C", "包裹D"]]
print([x for row in grid for x in row])          # 嵌套：外层 for 在前
weights = [1.2, 3.5, 1.2, 0.8]
print(sorted({round(w) for w in weights}))       # 集合推导式自动去重
```
→ 运行输出：`['包裹A', '包裹B', '包裹C', '包裹D'] ⏎ [1, 4]`
- **何时用/不用**：扁平化一层嵌套、批量去重用它；三层及以上或条件复杂，写 for + 临时变量。
- **锚点**：安检机把两排筐的件倒上同一条去重带，重复的滑进回收箱（`{}` 回收箱）。
- **易错**：`{}` 推导式必须带 `for`，`{1, 2}` 是字面量、`{}` 是空字典；嵌套 for 顺序写反结果完全不同。
- **关联**：`→ PY-04-12：三兄弟同语法` ｜ `→ PY-11 生成器表达式：小括号=惰性`。

## 六、出库三关（口号：拆包·排号·复印）

### PY-04-15 解包与星号解包 Unpacking
- **是什么**：`a, b = 序列` 按位置拆包；`first, *rest = 序列` 用星号收集剩余；可用来交换变量。
- **为什么**：一个包裹里三件货分给三个人 → 解包让"多值一次分发"替代逐个取下标 → 个数必须匹配否则 ValueError → 星号让"前若干 + 剩下一堆"不用数个数。
- **怎么写**：
```python
code, box, weight = ("SF001", "A-01", 1.5)    # 一一对应拆包
first, *rest = ["SF001", "SF002", "SF003"]    # *rest 收下剩余件
a, b = 1, 2; a, b = b, a                      # 元组解包交换
print(code, box, weight, first, rest, a, b)
```
→ 运行输出：`SF001 A-01 1.5 SF001 ['SF002', 'SF003'] 2 1`
- **何时用/不用**：函数多返回值、遍历 items、交换变量都用解包；只想取前几个又不关心余量用切片更直白。
- **锚点**：拆包裹分货：一人一件按顺序发，剩下的一股脑塞给"星号大袋子"（*rest）。
- **易错**：`*rest` 收到的永远是**列表**；个数不匹配实测抛 `ValueError: too many values to unpack (expected 2)`。
- **关联**：`→ PY-04-05：元组是解包的常用源` ｜ `→ PY-05-13：海象不能替代解包`。

### PY-04-16 排序：sorted 与 list.sort
- **是什么**：`sorted(x)` 返回新列表不改原数据；`x.sort()` 原地排返回 None；`key` 定排序依据，`reverse=True` 降序。
- **为什么**：按单号/重量出库是日常需求 → key 把每件货折算成"排序键"再比大小 → 多条件排序用元组 key（逐位比）→ sort 原地省空间，sorted 保原序更安全。
- **怎么写**：
```python
parcels = [("SF003", 2.0), ("SF001", 1.5), ("SF002", 2.0)]
print(sorted(parcels))                              # 默认按元组逐项比
print(sorted(parcels, key=lambda p: p[1]))          # 按重量
print(sorted(parcels, key=lambda p: (-p[1], p[0]))) # 重量降序 + 编号升序
names = ["包裹B", "包裹A"]; print(names.sort(), names)  # sort 原地返回 None
```
→ 运行输出：`[('SF001', 1.5), ('SF002', 2.0), ('SF003', 2.0)] ⏎ [('SF001', 1.5), ('SF003', 2.0), ('SF002', 2.0)] ⏎ [('SF002', 2.0), ('SF003', 2.0), ('SF001', 1.5)] ⏎ None ['包裹A', '包裹B']`
- **何时用/不用**：要保留原列表用 sorted；大列表只排一次用 sort；多级排序用元组 key（负号实现降序）。
- **锚点**：闭店前给货架"重新排号"：按面单编号贴新号牌，key 是那张写着依据的小纸条。
- **易错**：`x = x.sort()` 会把 x 变成 None；字符串按 Unicode 码点排，中文不是拼音序。
- **关联**：`→ PY-04-01：切片倒序 ≠ 排序` ｜ `→ PY-14 标准库：itemgetter 做 key`。

### PY-04-17 浅拷贝与深拷贝 Shallow vs Deep Copy
- **是什么**：浅拷贝只复制最外层（`copy()`、`list()`、`[:]`），深拷贝（`copy.deepcopy`）递归复制所有层。
- **为什么**：`b = a` 只是两个标签贴同一排货架 → 浅拷贝复制了外层货架，但嵌套的"子箱"仍是同一个 → 所以改嵌套内容两边都变 → 深拷贝连子箱里的货一起复制，代价是慢、元素要可拷。
- **怎么写**：
```python
import copy
station = {"网点1": ["包裹A", "包裹B"]}
shallow, deep = station.copy(), copy.deepcopy(station)
station["网点1"].append("包裹C")
print(shallow["网点1"], deep["网点1"])
```
→ 运行输出：`['包裹A', '包裹B', '包裹C'] ['包裹A', '包裹B']`
- **何时用/不用**：一层数据用 `[:]`/copy() 足够；嵌套容器要完全独立才 deepcopy；只是想要另一份可变副本别用 `=`。
- **锚点**：复印面单——浅拷贝只复印那张纸，深拷贝连箱子里的货也复制一份，两个箱子从此各走各的。
- **易错**：`b = a` 不是拷贝是同一件货；tuple 的浅拷贝往往还是它自己，真正坑人的只有嵌套可变对象。
- **关联**：`→ PY-02 变量与类型：可变/不可变` ｜ `→ PY-19 内存与性能：引用计数视角`。

## ⚔️ 对比消混表
| 易混点 | A | B | 判据 | 一句口诀 |
|---|---|---|---|---|
| append vs extend | 加一件（列表会套一层） | 一批逐件上架 | 传的是单件还是可迭代 | append 一件、extend 一批 |
| pop vs remove | 按货位取走并返回 | 按面单删第一件 | 参数是下标还是值 | pop 靠位、remove 靠值 |
| list vs tuple | 货架可增删改 | 塑封面单不许改 | 要不要写操作 | 要改用 list，不改用 tuple |

| 浅拷贝 vs 深拷贝 | 复印面单（外层） | 连货一起复制（全层） | 嵌套内部是否共享 | 浅拷外层、深拷全套 |

## ✅ 自测清单（合上本篇，先写再看）
1. 用一行代码把 `[3, 1, 2, 2]` 去重并升序输出。
> 答案：`sorted(set([3, 1, 2, 2]))` → `[1, 2, 3]`
2. `a = [1, 2]; b = a; b += [3]` 之后 a 是什么？为什么？
> 答案：`[1, 2, 3]`；`b = a` 是同一排货架，`+=` 原地 extend。
3. `t = (1, [2]); t[1].append(3)` 能执行吗？t 变成什么？
> 答案：能；`t == (1, [2, 3])`——元组只锁槽位不锁内容。
4. 如何按"字典的值"降序排键列表？`d = {"a": 2, "b": 5}`。
> 答案：`sorted(d, key=lambda k: d[k], reverse=True)` → `['b', 'a']`
5. 浅拷贝后改嵌套列表，为什么原对象也变了？
> 答案：浅拷贝只复制外层，嵌套的子箱还是同一个（见 PY-04-17）。
6. `x, *rest = "abc"` 后 rest 是什么类型？
> 答案：`['b', 'c']`，list 类型（星号永远收列表）。
