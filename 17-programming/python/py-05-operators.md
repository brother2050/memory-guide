## 一、收银计算器（口号：先算账后找零）

### PY-05-01 算术运算符 + - * /
- **是什么**：加减乘除四则；`/` 是真除法（true division），结果永远是 float。
- **为什么**：收银台算总价必须精确到分 → Python 3 把 `/` 定为真除法，`7/3` 不再截断成 2 → 行为更符合直觉 → 代价是整数相除也得 2.0 这种浮点结果。
- **怎么写**：
```python
print(7 + 3, 7 - 3, 7 * 3)
print(7 / 3, 6 / 3)                    # 真除法：结果总是 float
print(type(6 / 3).__name__)
```
→ 运行输出：`10 4 21 ⏎ 2.3333333333333335 2.0 ⏎ float`
- **何时用/不用**：金额、比例计算用 `/`；要丢掉小数部分用 `//`（见 PY-05-02），不要用 int() 截断做算术。
- **锚点**：收银台计算器上的四颗大键；`/` 键像一台"必须吐出小数"的验钞机。
- **易错**：`6 / 3` 是 `2.0` 不是 `2`，拿它当索引会抛 TypeError（要 int）。
- **关联**：`→ PY-05-02：整除与余数` ｜ `→ PY-02 变量与类型：int/float`。

### PY-05-02 整除 // 与取余 %（divmod）
- **是什么**：`//` 向下取整除法，`%` 取余数，`divmod(a, b)` 一次拿两样；两者都向下取整，余数与除数同号。
- **为什么**：找零时先给整张钞票、剩下的给硬币 → `//` 数整张、`%` 数硬币 → 负数时 Python 选"向下取整"保证 `a == (a//b)*b + a%b` 恒成立 → 所以 `-7 % 3` 是 2 而不是 -1。
- **怎么写**：
```python
print(7 // 3, 7 % 3, divmod(7, 3))     # 整除 / 余数 / 一次拿两样
print(-7 // 3, -7 % 3)                 # 向下取整：余数跟除数同号
print(10 % 2 == 0)                     # 取余判奇偶
```
→ 运行输出：`2 1 (2, 1) ⏎ -3 2 ⏎ True`
- **何时用/不用**：分页、分组、循环下标取模、奇偶判断用它们；要四舍五入用 `round()` 不是 `//`。
- **锚点**：找零台：`//` 数整张十元，`%` 是剩下的硬币；硬币面额（除数）决定余数的符号。
- **易错**：`-7 % 3 == 2`（跟除数同号）；浮点取余有精度尾巴，金额分账用整数"分"来算。
- **关联**：`→ PY-06-04：range 的步长配合 % 判周期` ｜ `→ PY-05-03：幂运算`。

### PY-05-03 幂运算 **
- **是什么**：`a ** b` 表示 a 的 b 次方，支持负数与小数指数（开方=0.5 次方）；`**` 是**右结合**。
- **为什么**：连乘同一商品（复利、面积、开方）用乘法写很啰嗦 → `**` 把"连乘"折叠成一个符号 → 右结合意味着 `2**3**2` 先算 `3**2` → 拿不准就加括号。
- **怎么写**：
```python
print(2 ** 10, 9 ** 0.5, 2 ** -1)      # 幂：连乘同一个数
print(2 ** 3 ** 2)                     # ** 右结合 = 2 ** (3 ** 2)
```
→ 运行输出：`1024 3.0 0.5 ⏎ 512`
- **何时用/不用**：开方用 `** 0.5` 或 `math.sqrt`；大整数幂会瞬间变巨大（`2**1000`），别在热循环里滥用。
- **锚点**：收银台的"翻堆"键：同一商品一摞摞翻倍堆放，`**` 右结合=右边那堆先堆起来。
- **易错**：`2 ** 3 ** 2 == 512` 不是 64；负底数要加括号 `(-2) ** 2`，否则解析成 `-(2**2)`。
- **关联**：`→ PY-05-14：优先级里 ** 最高且右结合`。

### PY-05-04 增强赋值 += -= *= 及其坑
- **是什么**：`a += b` 是"就地合并后回填"的简写，对可变对象多为原地修改（`__iadd__`），对不可变对象等于重新绑定。
- **为什么**：小票金额逐行滚加，`total = total + x` 写起来啰嗦 → 增强赋值压缩写法并允许原地优化 → 列表的 `+=` 是 extend 不是拼新表 → 于是有了"报错但值已变"的元组嵌套坑。
- **怎么写**：
```python
total = 0
total += 10          # 相当于 total = total + 10
total *= 2
print(total)
nums = [1, 2]
nums += [3]          # 列表的 += 是原地 extend
print(nums)
t = ([1],)
try:
    t[0] += [2]      # 坑：先原地改了，再往元组赋值 → 报错但值已变
except TypeError as e:
    print("TypeError:", e)
print(t[0])
```
→ 运行输出：`20 ⏎ [1, 2, 3] ⏎ TypeError: 'tuple' object does not support item assignment ⏎ [1, 2]`
- **何时用/不用**：累加/累乘/拼接用增强赋值；要保留旧值用 `b = a + x`（生成新对象）。
- **锚点**：小票打印机上的"滚加"键：新数直接滚进合计栏，同一张小票（对象）不换纸。
- **易错**：`t[0] += [2]` 抛 TypeError 但 `t[0]` 已经变成 `[1, 2]`——改用 `t[0].extend([2])` 才干净。
- **关联**：`→ PY-04-02：extend 语义` ｜ `→ PY-05-15：+= 背后是 __iadd__`。

## 二、验货天平（口号：称面值，认冠字号）

### PY-05-05 比较运算符与链式比较
- **是什么**：`== != > < >= <=` 返回 bool；Python 支持链式比较 `1 < x < 10`，等价于 `1 < x and x < 10` 且中间只算一次。
- **为什么**：验货天平要比轻重、比价签 → 比较运算产出"是/否"供后续判断 → 链式写法让区间判断贴近数学直觉 → 中间表达式只求值一次，避免副作用执行两次。
- **怎么写**：
```python
print(3 < 5, 3 != 3, 3 == 3.0)      # 比较结果是 bool
x = 4
print(1 < x < 10, 1 < x > 10)       # 链式比较 = and 串联
print("包裹A" < "包裹B")            # 字符串按 Unicode 码点比
```
→ 运行输出：`True False True ⏎ True False ⏎ True`
- **何时用/不用**：区间判断用链式；浮点相等别用 `==`（用 `math.isclose`）；大小比较只支持同类型可比对象。
- **锚点**：验货天平两端放货，指针只回答"高/低/平"；链式比较是把三个价签串成一串一次称完。
- **易错**：`3 == 3.0` 为 True（数值相等不看类型）；`float('nan') == float('nan')` 为 False，比较前先想清楚。
- **关联**：`→ PY-05-06：== 与 is 的分工` ｜ `→ PY-06-03：条件组合`。

### PY-05-06 身份运算符 is / is not
- **是什么**：`is` 判断"是不是同一个对象"（id 相同），`==` 判断"内容是否相等"。
- **为什么**：两件商品重量相同（`==`）不等于同一件商品（`is`）→ `is` 直接比内存地址，不走 `__eq__` → 所以速度恒定且语义严格 → 单例对象（None/True/False）一律用 is 判。
- **怎么写**：
```python
a = [1, 2]
b = [1, 2]
c = a
print(a == b, a is b, a is c)       # 内容同 / 不是同一件 / 是同一件
x = None
print(x is None, x is not None)
```
→ 运行输出：`True False True ⏎ True False`
- **何时用/不用**：判 None/True/False、判"同一对象"用 is；比数值/字符串内容用 `==`。
- **锚点**：两张 100 元 `==`（面值相等），但 `is` 是不是**同一张钞**——验钞机扫**冠字号**，同冠字号才是同一张。
- **易错**：小整数/短字符串有缓存，`x = 256; y = 256` 时 `x is y` 碰巧为 True，但这是实现细节，不能拿来判等。
- **关联**：`→ PY-04-05：不可变对象更常被复用` ｜ `→ PY-02 变量与类型：id() 与可变性`。

## 三、放行通道（口号：两道闸，短路放行）

### PY-05-07 逻辑运算符 and / or / not
- **是什么**：`and`（且）、`or`（或）、`not`（非）组合条件；它们返回**操作数本身**而非强制 bool。
- **为什么**：放行要"会员卡有效**且**未超时"两道闸都过 → and/or 把多个条件编成一条判定链 → 为了少写 if，Python 让 and/or 返回真实值 → 于是 `0 or "默认值"` 成了惯用兜底写法。
- **怎么写**：
```python
print(True and False, True or False, not True)
print(0 or "默认值", 1 and 2)       # and/or 返回操作数本身
print("" or "兜底", [] and [1])     # 空值当假用
```
→ 运行输出：`False True False ⏎ 默认值 2 ⏎ 兜底 []`
- **何时用/不用**：组合条件用 and/or/not；要求结果一定是 bool 请包 `bool(...)`，写进类型严格的 API 前先转换。
- **锚点**：收银通道两道审核闸：and=两道都要刷，or=刷一道就放，not=反向闸机。
- **易错**：`a and b` 在 a 为假时返回 a（不是 False）；`x = x or []` 会把合法的空值也替换成 []。
- **关联**：`→ PY-05-08：短路` ｜ `→ PY-05-09：真值表`。

### PY-05-08 短路求值 Short-Circuit
- **是什么**：and 左假不看右、or 左真不看右——右侧表达式（含函数调用）直接不执行。
- **为什么**：第一道审核没过就没必要开第二道扫描仪 → 短路省算力还天然防报错（如 `x and x[0]`）→ 右侧不执行意味着副作用也不会发生 → 依赖副作用的代码会"莫名没跑"。
- **怎么写**：
```python
def side(msg):
    print(msg)
    return True

print(True or side("or 右侧执行了吗"))
print(False and side("and 右侧执行了吗"))
print("上面没出现任何'执行了吗'字样 = 短路生效")
```
→ 运行输出：`True ⏎ False ⏎ 上面没出现任何'执行了吗'字样 = 短路生效`
- **何时用/不用**：用短路做"先判存在再取值"（`d and d["k"]`）；不要把必须执行的语句塞进 and/or 的右侧。
- **锚点**：第一道闸没刷开，第二道扫码枪压根不通电——"免检放行"其实是"免扫"。
- **易错**：`if f() and g():` 中 f() 为假时 g() 不执行，若 g() 有副作用（计数、写文件）就会漏执行。
- **关联**：`→ PY-05-07：返回操作数` ｜ `→ PY-12 异常：短路可当轻量防护`。

### PY-05-09 真值判断 truthy / falsy 与 any / all
- **是什么**：bool 上下文里 0、空容器、空串、None、False 为假，其余为真；`any` 有一个真即真，`all` 全真才真。
- **为什么**：收银员判断"购物车有没有东西"不想写 `len(x) > 0` → Python 约定空=假、非空=真 → 于是一个 if 能直接判容器 → 自定义对象默认为真（除非实现 `__bool__`/`__len__`）。
- **怎么写**：
```python
bag = []
print(bool(bag), bool([0]), bool(""))        # 空容器假、非空真
print(any([0, 0, 3]), all([1, 2, 0]))        # 任一真 / 全部真
```
→ 运行输出：`False True False ⏎ True False`
- **何时用/不用**：判空用 `if x:` / `if not x:`；要区分"0 和 None"这类具体值时别用真值判断，显式 `x is None`。
- **锚点**：空购物车过感应门不响（假），零元账单也算"没买"；any=一个顾客买单就开灯，all=全场都结账才关灯。
- **易错**：`bool([0])` 是 True（非空列表）；`any([])` 是 False、`all([])` 是 True（空集合的数学约定）。
- **关联**：`→ PY-05-07：逻辑运算消费的就是真值` ｜ `→ PY-06-01：if 的条件`。

## 四、扫码枪与零钱（口号：在不在，按位拆）

### PY-05-10 成员运算符 in / not in
- **是什么**：`x in 容器` 判断成员资格；对字符串是**子串**匹配，对 set/dict 是哈希查找。
- **为什么**：扫码枪要在会员名单里查卡号 → in 把"查找"写成一个符号 → 对 list 是逐个扫 O(n)，对 set/dict 平均 O(1) → 所以"大数据量常查"必须先转 set。
- **怎么写**：
```python
codes = {"SF001", "SF002", "SF003"}
print("SF002" in codes, "SF999" not in codes)   # set 查找平均 O(1)
print("SF" in "SF001")                          # 字符串按子串匹配
print([1, 2] in [[1, 2], [3]])                  # 列表按整元素匹配
```
→ 运行输出：`True True ⏎ True ⏎ True`
- **何时用/不用**：查值在不在用 in；要下标用 index；要键值映射用 dict 的 `in`。
- **锚点**：扫码枪"嘀"一声查会员名单：名单是纸条（list 逐个看）还是电脑（set 秒查）差别巨大。
- **易错**：`"SF" in "SF001"` 是 True（子串）但 `2 in [1, 2, 3]` 才是元素匹配；`in` 对 dict 只查键。
- **关联**：`→ PY-04-11：set 的 O(1) 查找` ｜ `→ PY-06-01：条件里高频使用`。

### PY-05-11 位运算符 & | ^ ~ << >>
- **是什么**：按二进制位操作：`&` 与、`|` 或、`^` 异或、`~` 取反（`~x == -x-1`）、`<<` 左移、`>>` 右移。
- **为什么**：找零时硬币按面值 1/2/4/8 分堆，任意金额都能拆成 2 的幂组合 → 位运算就是"按硬币面值拆/合" → 一次操作处理一个二进制位，速度极快 → 只对整数有效。
- **怎么写**：
```python
a, b = 0b1100, 0b1010
print(bin(a & b), bin(a | b), bin(a ^ b), bin(~a))
print(1 << 3, 8 >> 2)        # 左移乘 2、右移除 2
```
→ 运行输出：`0b1000 0b1110 0b110 -0b1101 ⏎ 8 2`
- **何时用/不用**：标志位、掩码、哈希组合、快速乘除 2 的幂用位运算；业务判断别为了"炫技"写位运算。
- **锚点**：零钱盘里的硬币面值 1/2/4/8——`&` 是两边都有的面值，`^` 是只在一边的面值，`~` 是反过来数硬币。
- **易错**：`~12 == -13` 不是按位取反得到 243（Python 整数无限长）；位运算不支持 float。
- **关联**：`→ PY-05-12：标志位实战` ｜ `→ PY-04-12：集合的 & | ^ 同形不同义`。

### PY-05-12 位运算实战：标志位与掩码
- **是什么**：用一个整数的每个二进制位表示一个开关（权限/状态），`|` 合并、`&` 查询、`&= ~` 清除。
- **为什么**：收银员权限若用多个布尔变量会越堆越多 → 一个整数 32 位可当 32 个开关 → 合并/查询/清除都是单条位运算 → 又快又省空间。
- **怎么写**：
```python
READ, WRITE = 1 << 0, 1 << 1      # 权限标志位：每种权限占一个二进制位
perm = READ | WRITE
print(bool(perm & READ), bool(perm & 4))    # 查某一位
perm &= ~WRITE                              # 清除某一位
print(bin(perm), bool(perm & WRITE))
```
→ 运行输出：`True False ⏎ 0b1 False`
- **何时用/不用**：开关集合（权限、选项、状态）用标志位；数据量大且语义复杂时改用 set/Enum 更可读。
- **锚点**：收银员胸前的权限牌：每颗别针=一个权限位，插上（|）拥有、拔掉（&= ~）收回、摸一下（&）就知道有没有。
- **易错**：`perm & READ == 0` 会被解析为 `perm & (READ == 0)`——`==` 优先级高于 `&`，查位务必写 `(perm & READ) == 0`。
- **关联**：`→ PY-05-11：位运算基础` ｜ `→ PY-17 typing：Enum/Flag 是可读替代`。

## 五、收银黑科技（口号：边扫边记，顺序口诀）

### PY-05-13 海象运算符 :=（3.8+）
- **是什么**：赋值表达式（assignment expression），在表达式内部"边算边把结果存进变量"，外号海象（`:=` 像海象的牙和眼）。
- **为什么**：`while (line := f.readline())` 这类"取值+判断"写两遍 → 海象把取值和判断合成一步 → 变量在外层作用域仍可用 → 于是避免重复计算/重复调用。
- **怎么写**：
```python
nums = [1, 4, 9]
roots = [(x, r) for x in nums if (r := int(x ** 0.5)) * r == x]  # 边算边记 r
print(roots)
data = ["2", "3", "x"]
it = iter(data)
while (item := next(it, None)) is not None:   # 一次取值直接判
    print("处理", item)
```
→ 运行输出：`[(1, 1), (4, 2), (9, 3)] ⏎ 处理 2 ⏎ 处理 3 ⏎ 处理 x`
- **何时用/不用**：值要"用两次"（判断+正文）时用海象；只用一次就别用，普通赋值更清楚。
- **锚点**：扫码枪边扫边把结果贴在手背上（`:=` 像贴标签的手），下一眼直接看手背，不必重扫。
- **易错**：海象必须写在括号里（`if (n := f()) > 0:`）；它在推导式/while 中创建的变量在外层可见，别撞名。
- **关联**：`→ PY-06-07：while 取值判断` ｜ `→ PY-17 typing：现代语法包`。

### PY-05-14 运算符优先级口诀
- **是什么**：同一表达式里运算符的结合顺序：括号 > `**` > 一元 > `* / // %` > `+ -` > 移位 > `&` > `^` > `|` > 比较/成员/身份 > `not` > `and` > `or`。
- **为什么**：不看优先级就会把 `a & b == 0` 算成 `a & (b == 0)` → Python 的优先级设计让"比较低于算术、逻辑最低" → 行为可预测但难背 → 治法是背短口诀 + 拿不准就加括号。
- **怎么写**：
```python
print(2 + 3 * 4)          # 先乘后加
print((2 + 3) * 4)        # 括号最高
print(not 1 == 2)         # 先比较后 not
print(1 + 2 > 2 * 1)      # 先算术后比较
```
→ 运行输出：`14 ⏎ 20 ⏎ True ⏎ True`
- **何时用/不用**：任何多运算符表达式都受它约束；真实代码里**加括号永远不丢分**。
- **锚点**：收银顺序口诀——「先扫码、再算账、再比价、最后放行」：算术 > 比较 > not > and > or；括号是 VIP 通道直接插队。
- **易错**：`not a == b` 是 `not (a == b)`；`a or b and c` 是 `a or (b and c)`；`**` 右结合（见 PY-05-03）。
- **关联**：`→ PY-05-12：& 与 == 的经典事故` ｜ `→ PY-06-03：条件组合`。

### PY-05-15 运算符背后的魔术方法预告
- **是什么**：运算符本质是方法调用——`a + b` 调 `a.__add__(b)`，`len(x)` 调 `x.__len__()`，`==` 调 `__eq__`。
- **为什么**：为什么 int/list/自定义类都能用 `+`？→ 因为解释器把符号翻译成双下划线方法（魔术方法/magic method）→ 类实现这些方法就获得运算符 → 所以"运算符行为"其实是类的协议设计。
- **怎么写**：
```python
print((1).__add__(2), [1, 2] + [3])        # + 背后是 __add__
print("ab".__len__(), len("ab"))           # len() 背后是 __len__
print([3, 1].__eq__([3, 1]), [3, 1] == [3, 1])
```
→ 运行输出：`3 [1, 2, 3] ⏎ 2 2 ⏎ True True`
- **何时用/不用**：日常写运算符即可；设计自定义类时才显式实现魔术方法（细节见 py-10）。
- **锚点**：收银台每个按键下面都贴着操作手册（`__add__`/`__len__`），按键只是外壳，手册才是规则。
- **易错**：重载 `__eq__` 后 Python 会把 `__hash__` 置为 None（对象不可哈希），需要一并重载。
- **关联**：`→ PY-10 魔术方法：完整协议表` ｜ `→ PY-05-06：== 与 is 的分野`。
