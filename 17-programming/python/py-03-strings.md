## 一、信件基本功

### PY-03-01 字符串与引号 String Literals
- **是什么**：字符串（string）是字符的有序序列；用 `'...'`、`"..."`、`"""..."""` 三种引号创建，前两者等价，三引号可换行。
- **为什么**：痛点：文本里本身含引号时会提前闭合 → 机制：三种引号互为转义出口，文本里有 `'` 就用 `"` 包 → 行为：任何引号组合都能表达 → 边界：三引号中间的换行属于字符串本身。
- **怎么写**：
```python
# test_33.py
print('单引号', "双引号")
print("""第一行
第二行""")
```
→ 运行输出：`单引号 双引号`；三引号串打印出两行 `第一行` / `第二行`
- **何时用/不用**：单行文本用 `"..."`（PEP 8 偏好）；多行文本、docstring 用三引号。
- **锚点**：一封信装进**三种信封**——小信封（单引号）、标准信封（双引号）、大横幅信封（三引号，能装一整段）。
- **易错**：`'他叫"小明"'` 没问题，但 `'他叫'小明''` 直接 `SyntaxError`；反斜杠结尾的字符串会"续行"到下一行。
- **关联**：`→ PY-01-08：docstring 就是三引号字符串`；`→ PY-03-02：引号前加 r 变 raw 信封`。

### PY-03-02 转义字符与 raw 字符串 Escape & Raw
- **是什么**：反斜杠 `\` 把字符转成特殊含义（`\n` 换行、`\t` 制表、`\'` 转义引号）；引号前加 `r` 让反斜杠原样保留（raw）。
- **为什么**：痛点：Windows 路径、正则里反斜杠成堆，写成转义又长又易错 → 机制：raw 字符串中 `\` 不再起转义作用 → 行为：`r'D:\code\new'` 直接原样 → 边界：raw 字符串仍不能以单个反斜杠结尾。
- **怎么写**：
```python
# test_34.py
print('D:\\code\\new')    # 手写双反斜杠
print(r'D:\code\new')     # raw 字符串更省事
print('说\'你好\'')
```
→ 运行输出：`D:\code\new` / `D:\code\new` / `说'你好'`
- **何时用/不用**：正则表达式一律 `r"..."`（PY-16）；普通中文文本不需要。
- **锚点**：`\` 是**特殊邮戳**——盖下去"n"就变"换行"；`r` 前缀是**免检信封**，邮戳盖了也不生效，原样送抵。
- **易错**：`'C:\new'` 里 `\n` 已被当换行，打印出来莫名断行；`r'C:\'` 语法错误（raw 不能以奇数个反斜杠收尾）。
- **关联**：`→ PY-16-02：正则模式几乎总是写成 raw 字符串`。

### PY-03-03 len() 与索引 Indexing
- **是什么**：`len(s)` 返回字符数；`s[i]` 取第 i 个字符（从 0 开始），`s[-1]` 取最后一个。
- **为什么**：痛点：要定位文本中的某个字 → 机制：字符串是序列（sequence），按下标 O(1) 取值 → 行为：正数从左数、负数从右数 → 边界：下标越界抛 `IndexError`。
- **怎么写**：
```python
# test_35.py
s = "记忆法"
print(len(s), s[0], s[-1])
```
→ 运行输出：`3 记 法`
- **何时用/不用**：取首尾字符、数长度用它；复杂截取用切片（PY-03-04）。
- **锚点**：信件**字数统计**与"从左数第几个字/倒数第几个字"——邮局按字数计费，按位置找字。
- **易错**：`s[3]` 对 3 个字的字符串是 `IndexError: string index out of range`；下标没有 0.5，`s[1.0]` 报 `TypeError`。
- **关联**：`→ PY-03-04：连续取多个字用切片`；`→ PY-03-15：len 数的是字符不是字节`。

### PY-03-04 切片 Slicing
- **是什么**：`s[start:stop:step]` 取子串：含 start、不含 stop、按 step 跳取；三个都可省略。
- **为什么**：痛点：取一段、隔一个取、反转，逐字符拼太啰嗦 → 机制：切片返回新字符串，越界不报错（自动截断）→ 行为：`s[::-1]` 就是反转 → 边界：`s[2:2]` 得空串；切片不改原串（PY-03-05）。
- **怎么写**：
```python
# test_36.py
s = "0123456789"
print(s[2:5], s[::2], s[::-1])
```
→ 运行输出：`234 02468 9876543210`
- **何时用/不用**：截取子串、反转、隔位取用切片；按模式匹配查找用字符串方法（PY-03-09）或正则（PY-16）。
- **锚点**：**裁信刀**——`[起:止:步长]` 就是"从第几格裁到第几格、隔几格裁一刀"；`[::-1]` 是把信倒着裁一遍。
- **易错**：`s[:10]` 不报错不代表有 10 个字符（越界自动截断）；`s[2:5]` 包含下标 2、3、4，不含 5。
- **关联**：`→ PY-04-11：列表/元组的切片语法与这里完全一致`。

### PY-03-05 字符串不可变 Immutability
- **是什么**：字符串创建后不能原地修改（immutable）；一切"修改"都是造新字符串。
- **为什么**：痛点：以为 `s[0] = 'x'` 能改字 → 机制：str 是不可变对象（PY-02-13），item 赋值不被支持 → 行为：改一个字必须拼出新串 → 边界：频繁拼接会造大量临时对象，大段拼接用 `join`（PY-03-07）。
- **怎么写**：
```python
# test_37.py
s = "信件"
try:
    s[0] = "密"
except TypeError as e:
    print(f"{type(e).__name__}: {e}")
s = "密" + s[1:]      # 重写一封
print(s)
```
→ 运行输出：`TypeError: 'str' object does not support item assignment` / `密件`
- **何时用/不用**：改内容一律造新串；在循环里 `s += x` 慢，改用列表收集再 join。
- **锚点**：**信写完就封口**——想改一个字，只能撕了重写一封新信（新对象），旧信原样不动。
- **易错**：`s.strip()` 之后还用旧变量以为原串被清理了（其实返回新串）；把 `s.replace()` 当原地修改。
- **关联**：`→ PY-02-13：不可变家族还有 int/float/tuple`；`→ PY-19-03：不可变对象天然免拷贝`。

## 二、分拣处理台

### PY-03-06 strip() 清理首尾
- **是什么**：`strip()` 去掉首尾的空白字符，返回新串；`lstrip()/rstrip()` 只去左/右；可传参数去指定字符。
- **为什么**：痛点：用户输入、抓取文本常带前后空格与换行，直接比较会失败 → 机制：只处理首尾，中间不动 → 行为：`"  a  ".strip()` 得 `"a"` → 边界：中间空格要清得用 `replace`（PY-03-08）。
- **怎么写**：
```python
# test_38.py
raw = "  你好，世界  \n"
print(f"[{raw.strip()}]")
print(f"[{raw.rstrip()}]")
```
→ 运行输出：`[你好，世界]` / `[  你好，世界]`
- **何时用/不用**：处理 input()、读文件行（PY-15）必用；本身干净的字面量不必。
- **锚点**：**撕掉信封周边多余的纸毛边**——只撕边角（首尾），不拆信（中间内容不动）。
- **易错**：`strip("0")` 是去首尾的字符 0，不是去空白；全角空格 `　` 不会被默认 strip 去掉。
- **关联**：`→ PY-02-10：input() 的结果先 strip 再转换最稳`。

### PY-03-07 split() 与 join()
- **是什么**：`split(分隔符)` 把字符串拆成列表；`join(可迭代)` 用指定连接符把列表拼回字符串，两者互逆。
- **为什么**：痛点：CSV 行、日志行要拆字段；一堆字段又要拼回一行 → 机制：split 按分隔符切分生成 list，join 按连接符合并 → 行为：`"a,b".split(",")` ↔ `",".join(["a","b"])` → 边界：`split()` 不给参数按任意空白拆，`"".join` 是无分隔拼接。
- **怎么写**：
```python
# test_39.py
cities = "北京,上海,广州".split(",")
print(cities)
print(" | ".join(cities))
```
→ 运行输出：`['北京', '上海', '广州']` / `北京 | 上海 | 广州`
- **何时用/不用**：解析文本用 split，生成文本用 join；循环里 `"+".join(parts)` 优于逐个 `+=`。
- **锚点**：`split` 是**拆信**（按封口线拆成一页页纸），`join` 是**把几张纸糊进同一个信封**（信封上的纹样就是连接符）。
- **易错**：`split(",")` 遇到 `"a,,b"` 会得到空串 `'['a', '', 'b']'`；`join` 的元素必须全是 str，混有 int 直接 `TypeError`。
- **关联**：`→ PY-04-01：拆出来的结果就是列表（list）`。

### PY-03-08 replace() 替换
- **是什么**：`replace(旧, 新, 次数)` 返回把旧子串替换后的新串，次数可限。
- **为什么**：痛点：批量改正错字、脱敏、清格式 → 机制：顺序扫描替换所有匹配（或前 n 次）→ 行为：不改原串，返回新串 → 边界：不支持正则，模式匹配换 `re.sub`（PY-16）。
- **怎么写**：
```python
# test_40.py
s = "寄往旧地址"
print(s.replace("旧", "新"))
```
→ 运行输出：`寄往新地址`
- **何时用/不用**：简单字面替换用 replace；按规则替换（如"所有数字"）用正则。
- **锚点**：**改寄批条**——在信封上贴一张"旧址改新址"的批条，全信批条贴完再送出（新信封出街）。
- **易错**：`s.replace("a", "")` 是删除所有 a；替换是区分大小写的。
- **关联**：`→ PY-03-05：replace 也返回新串，原串不变`；`→ PY-16-05：re.sub 接管模式替换`。

### PY-03-09 查找与判断 find/in/startswith
- **是什么**：`in` 判断子串存在；`find(子串)` 返回首个下标（找不到返回 -1）；`startswith/endswith` 判首尾；`count` 数出现次数。
- **为什么**：痛点：要确认"这段文本里有没有某段、在哪里、开头是什么" → 机制：一次扫描完成子串匹配 → 行为：布尔判断 + 下标定位一步到位 → 边界：find 找不到返回 -1，别当下标直接用。
- **怎么写**：
```python
# test_41.py
s = "订单号20261006"
print(s.find("号"), "2026" in s)
print(s.startswith("订单"), s.endswith("06"), s.count("0"))
```
→ 运行输出：`2 True` / `True True 3`
- **何时用/不用**：快速判断用 `in`/`startswith`；要位置用 `find`；要复杂模式用正则（PY-16）。
- **锚点**：**查信件上的邮编与邮戳**——先问"有没有"（in），再问"在第几格"（find），最后看"是不是某地邮戳"（startswith）。
- **易错**：`find` 返回 -1 时当成真下标会取出意料之外的字符；`s.index("x")` 找不到会抛 `ValueError`（find 则返回 -1）。
- **关联**：`→ PY-05-07：in 同时是容器的成员运算符`。

## 三、盖章格式化

### PY-03-10 f-string 格式控制
- **是什么**：f-string 的 `{}` 内可写 `表达式:格式规格`，控制宽度、对齐、精度、百分比、千分位。
- **为什么**：痛点：报表要对齐、金额要留两位小数、数字要千分位 → 机制：格式规格 mini-language 按槽位套用 → 行为：`f"{pi:.2f}"`、`f"{n:>6}"`、`f"{x:.1%}"`、`f"{big:,}"` → 边界：规格符与表达式类型要匹配（`:.2f` 只给数字）。
- **怎么写**：
```python
# test_42.py
pi, n, x = 3.14159, 42, 0.25
print(f"{pi:.2f}")
print(f"{n:>6}|")
print(f"{x:.1%}")
print(f"{1234567:,}")
```
→ 运行输出：`3.14` / `␣␣␣␣42|`（42 右对齐占 6 格）/ `25.0%` / `1,234,567`
- **何时用/不用**：报表、日志、对齐输出必用；简单拼接不用写规格。
- **锚点**：**盖章模板**——章框固定宽度（`>6` 右对齐），金额永远留两位（`:.2f`），章盖下去整整齐齐。
- **易错**：`f"{x:.2f}"` 用在字符串上报 `ValueError: Unknown format code 'f' for object of type 'str'`；`%` 规格是百分比显示，不是取模。
- **关联**：`→ PY-02-16：f-string 的基础插值`。

### PY-03-11 str.format() 模板填空
- **是什么**：`"模板{槽位}".format(值)` 用位置参数 `{0}`、命名参数 `{名}` 填充模板，可复用、乱序。
- **为什么**：痛点：同一模板要换着顺序填、同一值出现多次 → 机制：槽位与参数按位置/名字绑定 → 行为：`"{1} 年 {0} 月"` 乱序照样填对 → 边界：语法比 f-string 啰嗦，新代码优先 f-string。
- **怎么写**：
```python
# test_43.py
print("{1} 年 {0} 月".format(10, 2026))
print("{city}欢迎你".format(city="苏州"))
```
→ 运行输出：`2026 年 10 月` / `苏州欢迎你`
- **何时用/不用**：模板与数据分离时（模板存配置里）用它；同作用域直接插值用 f-string。
- **锚点**：**空白信封模板填空**——信封上印好"___ 年 ___ 月"，按编号把内容塞进空格，空格编号可以不按顺序。
- **易错**：槽位编号写成 `{1}` 但只给了 1 个参数，抛 `IndexError`；命名参数名拼错抛 `KeyError`。
- **关联**：`→ PY-03-10：新代码用 f-string 更短`；`→ PY-03-12：% 是更老的一代模板`。

### PY-03-12 %-格式化（了解）
- **是什么**：`"格式" % 值` 是 C 语言风格的老式格式化：`%s` 字符串、`%d` 整数、`%.2f` 浮点。
- **为什么**：痛点：大量存量代码用它，读不懂就改不动 → 机制：占位符按顺序与元组匹配 → 行为：`"%s 今年 %d 岁" % ("小明", 18)` → 边界：元组个数不匹配抛 `TypeError`，新代码不必再写。
- **怎么写**：
```python
# test_44.py
print("%s 今年 %d 岁" % ("小明", 18))
print("%.2f" % 3.14159)
```
→ 运行输出：`小明 今年 18 岁` / `3.14`
- **何时用/不用**：维护老代码时能读懂即可；新代码用 f-string（PY-03-10）。
- **锚点**：**老式铅字排版印章**——字模位（%s/%d）排好，铅字（值）一个个按顺序嵌进去，嵌错位整行印歪。
- **易错**：`"%d" % "3"` 抛 `TypeError`（不做隐式转换）；单个值不用包元组，多个值必须包。
- **关联**：`→ PY-03-10/11：三代格式化按 f-string > format > % 排优先级`。

## 四、国际邮务：文本与字节

### PY-03-13 Unicode 与 ord()/chr()
- **是什么**：每个字符对应一个码点（code point），`ord(字符)` 给出码点，`chr(码点)` 还原字符。
- **为什么**：痛点：要比大小、做字符运算、处理生僻字 → 机制：Unicode 把全球字符编成统一序号 → 行为：`ord("中")` 得 20013 → 边界：字符不等于字节（PY-03-15），`len("中a")` 数的是 2 个字符。
- **怎么写**：
```python
# test_45.py
print(ord("中"), chr(20013), len("中a"))
```
→ 运行输出：`20013 中 2`
- **何时用/不用**：字符运算、加密玩具、大小写偏移用它；日常文本处理用不到。
- **锚点**：每个字在**电报码本**上有唯一编号——字→码（ord），码→字（chr），查号与反查一翻即得。
- **易错**：`ord("ab")` 抛 `TypeError: ord() expected a character`；emoji 可能由多个码点组合，`len("👍")` 可能为 2。
- **关联**：`→ PY-03-14：码点落盘时才要编码成字节`。

### PY-03-14 encode() 与 decode() 与 bytes
- **是什么**：`str.encode(编码名)` 把文本编码成字节（bytes）；`bytes.decode(编码名)` 反向解码回文本。
- **为什么**：痛点：磁盘与网络只传字节，不传"字符" → 机制：UTF-8/GBK 等编码规则把码点序列映射成字节序列 → 行为：`"中文".encode("utf-8")` 得 6 字节 → 边界：编码名不匹配就乱码或报错（PY-03-15）。
- **怎么写**：
```python
# test_46.py
b = "中文".encode("utf-8")
print(b, len(b))
print(b.decode("utf-8"))
```
→ 运行输出：`b'\xe4\xb8\xad\xe6\x96\x87' 6` / `中文`
- **何时用/不用**：读写文件、网络传输、哈希前必经此步；纯内存里的文本操作不需要。
- **锚点**：**寄国际信要装进标准邮袋**（encode：文字→字节邮袋），收件国按当地规则拆袋（decode：字节→文字）。
- **易错**：`b"中文"` 这种字面量写法报 `SyntaxError`（bytes 里只能放 ASCII）；decode 时编码名写错直接 `UnicodeDecodeError`。
- **关联**：`→ PY-15-03：open() 的 encoding 参数就是这套规则`；`→ PY-02-09：类型转换是"换包装"，encode 是"装袋出境"，机制不同`。

### PY-03-15 编码坑：UTF-8 与 GBK
- **是什么**：同一段文本用不同编码得到不同字节数；用错编码解码会乱码或报错——中文环境最常见的坑是 UTF-8 与 GBK 混用。
- **为什么**：痛点：Windows 记事本默认 GBK 存文件，Linux 读取按 UTF-8 就炸 → 机制：两种编码对"中"分别占 3 字节与 2 字节，字节序列互不兼容 → 行为：`len("中文")` 是 2，UTF-8 编码后 6 字节，GBK 编码后 4 字节 → 边界：`errors="ignore/replace"` 能强行解码但会丢字/出 `�`。
- **怎么写**：
```python
# test_47.py
s = "中文"
print(len(s), len(s.encode("utf-8")), len(s.encode("gbk")))
try:
    s.encode("gbk").decode("utf-8")
except UnicodeDecodeError as e:
    print(f"{type(e).__name__}: {e}")
```
→ 运行输出：`2 6 4` / `UnicodeDecodeError: 'utf-8' codec can't decode byte 0xd6 in position 0: invalid continuation byte`
- **何时用/不用**：跨系统交换文件、读历史数据前先确认编码；新项目一律 UTF-8。
- **锚点**：同一个"中"字，**英文邮袋装 3 格、方言邮袋（GBK）装 2 格**——拿错袋单拆包，不是缺字就是整包拒收（报错）。
- **易错**：`len(bytes)` 当字符数用导致按字节切片切出半个汉字；open 不写 encoding 时不同操作系统默认值不同（PY-15）。
- **关联**：`→ PY-03-13：字符与码点是"文字层"，编码是"字节层"`；`→ PY-15-04：文件读写的编码参数`。

## 五、分拣流水线

### PY-03-16 遍历与成员判断 in
- **是什么**：`for ch in s` 逐字符遍历；`子串 in s` 判断存在性（返回 bool）。
- **为什么**：痛点：要逐字处理或确认内容 → 机制：字符串是可迭代对象（iterable，PY-11），`in` 走子串匹配 → 行为：遍历拿到的每个 `ch` 都是单字符 str → 边界：`in` 对字符串是子串判断，对列表是元素判断（PY-04）。
- **怎么写**：
```python
# test_48.py
for ch in "abc":
    print(ch, end=" ")
print()  # 换行
print("b" in "abc", "z" in "abc")
```
→ 运行输出：`a b c ` / `True False`
- **何时用/不用**：统计字符、逐字校验用它；大文本循环太慢时用 C 级方法（count/replace）。
- **锚点**：**邮差逐字投递**挨家挨户送（遍历）；问"这片区里有没有某户"（in）一嗓子就有答案。
- **易错**：`for` 里试图 `ch = ...` 修改原串（不可变，PY-03-05）；`"ab" in "abc"` 为 True 说明 in 查的是子串不是字符。
- **关联**：`→ PY-05-07：成员运算符 in/not in 的总表`；`→ PY-11-01：字符串是可迭代对象`。

### PY-03-17 实战组合：清洗-拆分-重组
- **是什么**：把 strip/split/replace/join 按流水线顺序组合，是文本处理的通用套路。
- **为什么**：痛点：真实文本又脏又带格式（空格、换行、多余符号）→ 机制：每一步都是纯函数返回新串，可自由串联 → 行为：先整体清洗、再拆字段、逐字段精修、最后重组 → 边界：字段个数不固定时 split 后要检查长度再取值。
- **怎么写**：
```python
# test_49.py
raw = "  张三, 138-0000-0000 \n"
parts = raw.strip().split(",")
name, phone = parts[0].strip(), parts[1].strip().replace("-", "")
print(name, phone)
```
→ 运行输出：`张三 13800000000`
- **何时用/不用**：处理日志行、CSV 行、用户粘贴文本都用这套；结构化数据用 csv/json 模块（PY-15）。
- **锚点**：邮局**分拣流水线**——先撕毛边（strip）、按分拣线拆开（split）、逐件精修（strip/replace）、装回同一封（join/print）。
- **易错**：没先 `strip()` 就 split，字段里带空格导致比较失败；`parts[1]` 在字段不足时抛 `IndexError`。
- **关联**：`→ PY-03-06~08：流水线上的三台机器`；`→ PY-04-11：拆出的多个字段可用解包一次拿走`。

## ✅ 自测清单（合上本篇，先写再看）

1. 不运行，说出 `print('C:\new')` 的输出形态，并给出两种修复写法。
> 答案：`C:` 换行 `ew`（`\n` 被当换行）；写 `r'C:\new'` 或 `'C:\\new'`。
2. 用一行代码把 `"a,b,c"` 反转成 `"c-b-a"`（提示：split + 切片 + join）。
> 答案：`"-".join("a,b,c".split(",")[::-1])` → `c-b-a`。
3. `s = "订单号20261006"`，`s.find("无")` 得什么？直接当索引用会怎样？
> 答案：`-1`；`s[-1]` 会取到最后一个字符 `'6'`，静默出错，所以先判断是否 `-1`。
4. 为什么 `len("中文")` 是 2，而 `len("中文".encode("utf-8"))` 是 6？
> 答案：前者数字符（2 个），后者数字节，UTF-8 下每个中文占 3 字节（GBK 是 2 字节）。
5. `f"{3.14159:.2f}"`、`f"{42:>6}"`、`f"{0.25:.1%}"` 各输出什么？
> 答案：`3.14`；`␣␣␣␣42`（右对齐占 6 格）；`25.0%`。
