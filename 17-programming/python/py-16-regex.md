## 一、可疑特征卡（元字符）

### PY-16-01 正则与 re 模块初识 Regular Expression
- **是什么**：正则表达式（regular expression）是描述文本模式的迷你语言；`re` 模块负责编译与匹配，`re.findall(模式, 文本)` 找出全部匹配。
- **为什么**：按固定格式抽信息（数字、日期）用字符串切片脆如蛋壳，格式稍变就崩 → 正则用"模式"描述一整类文本 → 行为：模式匹配的是字符形状不是语义 → 边界：嵌套格式（HTML/JSON）该用专用解析器。
- **怎么写**：
```python
import re
text = "订单A-2026 金额100元 订单B-2027 金额250元"
print(re.findall(r"\d+", text)); print("扫描模块就绪:", re.__name__)
```
→ 运行输出：`['2026', '100', '2027', '250']` ｜ `扫描模块就绪: re`
- **何时用/不用**：校验、抽取、替换用 re；一行能写清的字符串方法（`str.split/find`）更直白。
- **锚点**：安检扫描仪开机：整包行李（文本）过机器，按通缉图案（模式）把可疑物全部捞出来。
- **易错**：`\d` 在普通字符串里被当转义序列警告，模式一律写 `r"..."`（PY-16-04）。
- **关联**：`→ PY-16-10：match/search 等五个操作`；`→ PY-14-15：re 在标准库中的定位`。

### PY-16-02 元字符 `. ^ $ \d \w \s` Metacharacters
- **是什么**：元字符是"形状卡"：`.` 任意单字符、`\d` 数字、`\w` 字母数字下划线（Unicode）、`\s` 空白、`^` 行首、`$` 行尾。
- **为什么**：不能把每个可能的字符都写出来（数字 0-9 就十种）→ 用形状卡概括一类 → 行为：`^/$` 匹配的是位置不是字符 → 边界：`.` 默认不匹配换行（见 re.S，PY-16-13）。
- **怎么写**：
```python
import re
print(". 捞 a?c:", re.findall(r"a.c", "abc|ac|axc")); print(r"\d+ 抽数字:", re.findall(r"\d+", "温度25度 湿度60%"))
print(r"\s 抓空白:", re.findall(r"\s", "a b\tc")); print("行首^行尾$:", bool(re.search(r"^订单", "订单2026")), bool(re.search(r"2026$", "订单2026")))
```
→ 运行输出：`. 捞 a?c: ['abc', 'axc']` ｜ `\d+ 抽数字: ['25', '60']` ｜ `\s 抓空白: [' ', '\t']` ｜ `行首^行尾$: True True`
- **何时用/不用**：数字用 `\d`、单词用 `\w`；要精确白名单用字符类（PY-16-03）。
- **锚点**：可疑特征卡：`.` 任意行李、`\d` 疑似数字形状、`\w` 疑似字母数字、`\s` 空隙、`^/$` 行李队伍的头尾。
- **易错**：`ac` 不匹配 `a.c`（点必须占一个字符）；`\w` 认汉字（Unicode），别以为只认 ASCII。
- **关联**：`→ PY-16-03：[] 自选形状`；`→ PY-16-05：\d+ 加量词才有用`。

### PY-16-03 字符类 `[ ]` 与取反 `[^ ]` Character Classes
- **是什么**：`[aeiou]` 自选网眼规格（匹配其中任一字符）、`[0-9]` 范围、`[^aeiou]` 取反（除这些都匹配）。
- **为什么**：`\w` 范围太宽（连汉字都收）→ 字符类给出"只认这几样"的白名单 → 行为：类里多数字符按字面意思，量词可叠加在类上 → 边界：`]`、`-`、`^` 在类内有特殊位置写法。
- **怎么写**：
```python
import re
print("[aeiou] 捞元音:", re.findall(r"[aeiou]+", "hello")); print("[0-9]{2} 数字段:", re.findall(r"[0-9]{2}", "a12b345"))
print("[^aeiou] 非元音:", re.findall(r"[^aeiou]+", "hello"))
```
→ 运行输出：`[aeiou] 捞元音: ['e', 'o']` ｜ `[0-9]{2} 数字段: ['12', '34']` ｜ `[^aeiou] 非元音: ['h', 'll']`
- **何时用/不用**：限定字符集用 `[...]`；想表达"不是某词"用否定前瞻（PY-16-18 的技巧）而不是 `[^...]`。
- **锚点**：自选渔网网眼规格：`[abc]` 网眼只漏这三种鱼，`[^abc]` 除这三种全捞上来。
- **易错**：`[^abc]` 里的是"取反"不是"按顺序 abc"；`[0-9]{2}` 找 "12345" 会得到 `['12','34']`（5 落单）。
- **关联**：`→ PY-16-02：形状卡是预设规格`；`→ PY-16-05：类上加量词`。

### PY-16-04 转义与原始字符串 `r""` Escaping & Raw Strings
- **是什么**：想匹配元字符本身要加 `\`（`\.` 匹配点、`\*` 匹配星号）；`r"..."` 原始字符串让 `\` 原样进正则，不再被 Python 字符串层先转义一遍。
- **为什么**：正则已经满是 `\`，Python 字符串层再吃掉一层 → 双重转义地狱（`"\\d"` 难读易错）→ 行为：`r"\d"` 里 `\d` 原样到正则引擎 → 边界：原始字符串末尾不能放单个 `\`。
- **怎么写**：
```python
import re
print("普通 '\\n' 是换行:", repr("\n"), "| 原始 r'\\n' 是两字符:", repr(r"\n")); print("转义后匹配字面点:", re.findall(r"3\.14", "圆周率3.14"), re.findall(r"3\.14", "3x14"))
print("不转义的 . 通吃:", re.findall(r"3.14", "3x14"))
```
→ 运行输出：`普通 '\n' 是换行: '\n' | 原始 r'\n' 是两字符: '\\n'` ｜ `转义后匹配字面点: ['3.14'] []` ｜ `不转义的 . 通吃: ['3x14']`
- **何时用/不用**：正则模式一律 `r"..."`；只写普通文本不需要。
- **锚点**：给通缉令贴保护膜（`r""`）：膜内的 `\` 原样保留，不被翻译官（字符串层）先啃一口。
- **易错**：`"3\.14"` 与 `r"3\.14"` 结果一样但前者在复杂模式里会失手；`r"C:\new\"` 语法错误（结尾裸 `\`）。
- **关联**：`→ PY-16-02：元字符需要转义才能当字面`。

## 二、网眼松紧绳（量词）

### PY-16-05 量词 `* + ? {n,m}` Quantifiers
- **是什么**：量词规定"前面的元素捞几条"：`*` 0 条起、`+` 至少 1 条、`?` 0 或 1 条、`{2,3}` 限定 2~3 条。
- **为什么**：数字串长度不定、单词长短不一 → 精确写死长度不现实 → 量词给"松紧度" → 行为：量词只约束紧邻的前一个元素 → 边界：`ab*` 是 `a` 后跟任意个 `b`，不是任意个 `ab`。
- **怎么写**：
```python
import re
print("* 任意次:", re.findall(r"ab*", "a ab abb")); print("+ 至少一次:", re.findall(r"ab+", "a ab abb"))
print("? 可有可无:", re.findall(r"colou?r", "color colour")); print("{2,3} 限定条数:", re.findall(r"\d{2,3}", "1 12 123 1234"))
```
→ 运行输出：`* 任意次: ['a', 'ab', 'abb']` ｜ `+ 至少一次: ['ab', 'abb']` ｜ `? 可有可无: ['color', 'colour']` ｜ `{2,3} 限定条数: ['12', '123', '123']`
- **何时用/不用**：长度不定用 `*`/`+`，可选字符用 `?`，严格格式（手机号）用 `{n}`；想"多元素打包重复"用分组（PY-16-07）。
- **锚点**：渔网松紧绳：`*` 松到零条、`+` 至少一条、`?` 可有可无、`{n,m}` 规定条数上限下限。
- **易错**：`\d{2,3}` 对 "1234" 捞出 `123` 而不是 `1234`（贪婪取上限但不超）；量词前忘了写元素（如 `*` 开头）直接报错。
- **关联**：`→ PY-16-06：量词的贪婪开关`；`→ PY-16-03：量词常挂在字符类上`。

### PY-16-06 贪婪与懒惰 Greedy vs Lazy
- **是什么**：默认贪婪（greedy）：量词尽量多捞；加 `?` 变懒惰（lazy）：尽量少捞（`.*?`、`+?`、`??`）。
- **为什么**：`<b>.*</b>` 想抓一个标签却把两个标签连中间全吞（跨段匹配）→ 懒惰量词"够用就停" → 行为：引擎先尝试最长，回吐到能匹配为止 → 边界：两者匹配的"起点"相同，只是"终点"不同。
- **怎么写**：
```python
import re
s = "<b>三国</b>和<b>西游</b>"
print("贪婪 .*:", re.findall(r"<b>.*</b>", s)); print("懒惰 .*?:", re.findall(r"<b>.*?</b>", s)); print("+? 只捞一个:", re.findall(r"\d+?", "123"))
```
→ 运行输出：`贪婪 .*: ['<b>三国</b>和<b>西游</b>']` ｜ `懒惰 .*?: ['<b>三国</b>', '<b>西游</b>']` ｜ `+? 只捞一个: ['1', '2', '3']`
- **何时用/不用**：取两标记之间的最短片段用懒惰；取到行尾/整段用贪婪。配 `[^>]*` 限定范围更稳。
- **锚点**：两种撒网手法：贪婪一网捞到最多再往回吐，懒惰捞够用就收网。
- **易错**：对没有明确结尾标记的文本，懒惰也会捞错；`.*?` 在只想匹配空串时多此一举。
- **关联**：`→ PY-16-05：量词的默认行为`。

## 三、渔网分格兜（分组）

### PY-16-07 分组 `( )` 与捕获 Grouping & Capturing
- **是什么**：`()` 把模式的一部分装进"格子"：整体匹配之外，各组可单独取（`m.group(1)`）；`\1` 反向引用"和第 1 组一样的内容"。
- **为什么**：只要日期里的年份、拆 `"名字@域名"` → 直接匹配拿不到分段 → 分组把匹配结果拆成结构 → 行为：`findall` 带组时返回各组元组 → 边界：组号按左括号顺序从 1 数。
- **怎么写**：
```python
import re
m = re.search(r"(\d{4})-(\d{2})", "日期2026-10-06")
print("整体:", m.group(0), "| 组1:", m.group(1), "| 组2:", m.group(2)); print("findall 带组:", re.findall(r"(\w+)@(\w+)", "a@x b@y")); print("反向引用 \\1:", re.findall(r"(\d)-\1", "1-1 2-3"))
```
→ 运行输出：`整体: 2026-10 | 组1: 2026 | 组2: 10` ｜ `findall 带组: [('a', 'x'), ('b', 'y')]` ｜ `反向引用 \1: ['1']`
- **何时用/不用**：要拆字段就分组；只想"整体匹配不拆"时用 `(?:...)` 非捕获组省开销。
- **锚点**：渔网分格兜：一网捞上来的鱼按格分装，每格单独过秤（group）；`\1` 是"这格和第 1 格长得一样"。
- **易错**：`group(0)` 永远是整体，`group(1)` 才是第一格；组号数错（多层括号嵌套）取错字段。
- **关联**：`→ PY-16-08：给格子贴名字更好读`；`→ PY-16-11：findall 带组返回结构不同`。

### PY-16-08 命名分组 `(?P<name>...)` Named Groups
- **是什么**：给分组起名字：`(?P<y>\d{4})`，之后用 `m.group("y")`、`m.groupdict()` 按名字取，不用数括号。
- **为什么**：字段一多 `group(5)` 谁知道是什么 → 命名分组把"位置记忆"换成"名字记忆" → 行为：`groupdict()` 直接得到字段字典 → 边界：名字只能字母数字下划线，同模式内唯一。
- **怎么写**：
```python
import re
m = re.search(r"(?P<y>\d{4})-(?P<m>\d{2})-(?P<d>\d{2})", "2026-10-06 开幕")
print(m.group("y"), m.group("m"), m.group("d"))
print("全部命名组:", m.groupdict())
```
→ 运行输出：`2026 10 06` ｜ `全部命名组: {'y': '2026', 'm': '10', 'd': '06'}`
- **何时用/不用**：字段 ≥3 个一律命名分组；两三组的简单模式用普通组即可。
- **锚点**：给每个网兜贴标签（`?P<名字>`）：取鱼按标签名拿，不用数"第几格"。
- **易错**：`(?P<y>...)` 里的 `P` 是大写；`group("Y")` 大小写不符抛 `IndexError`。
- **关联**：`→ PY-16-17：日志解析是命名分组主场`。

### PY-16-09 选择 `|` Alternation
- **是什么**：`|` 表示"或"：`液体|电池|超规` 匹配三者之一；与 `()` 搭配限定选项范围（`(苹果|香蕉)汁`）。
- **为什么**：同位置有多种合法写法（分隔符 `-` 或 `/`、多个关键词）→ 选择分支一次写清 → 行为：从左到右尝试，第一个成功即定 → 边界：分支过长会回溯爆炸，能用字符类就别用 `|`。
- **怎么写**：
```python
import re
print("三通道分流:", re.findall(r"液体|电池|超规", "行李含电池和超规物品"))
print("与分组搭配:", re.findall(r"(苹果|香蕉)汁", "苹果汁 香蕉汁 橙汁"))
```
→ 运行输出：`三通道分流: ['电池', '超规']` ｜ `与分组搭配: ['苹果', '香蕉']`
- **何时用/不用**：多关键词/多格式并存用 `|`；单字符多选一用 `[...]`（PY-16-03）。
- **锚点**：安检通道分流：`|` 像三条并排通道——液体/电池/超规，各走各的，谁先符合谁过。
- **易错**：`|` 优先级最低：`ab|cd` 是 `ab` 或 `cd`，`a(b|c)d` 才是 `abd`/`acd`。
- **关联**：`→ PY-16-07：分组圈定选择范围`。

## 四、扫描操作台（re 模块 API）

### PY-16-10 `match` vs `search`：定点检查 vs 全场巡逻
- **是什么**：`re.match` 只从字符串**开头**尝试匹配；`re.search` 从**全场**找第一处；两者都返回 Match 对象或 `None`。
- **为什么**：校验"整串是否合法"和"文本里有没有"是两种问题 → match 管开头、search 管全场 → 行为：match 不能锚定结尾，整串校验加 `$` 或用 `fullmatch` → 边界：`match(r"\d+", "12a")` 也成功（只中前缀）。
- **怎么写**：
```python
import re
s = "单号: 2026"
print("match:", re.match(r"\d+", s)); print("search:", re.search(r"\d+", s).group()); print("match 带前缀:", re.match(r"单号: (\d+)", s).group(1))
```
→ 运行输出：`match: None` ｜ `search: 2026` ｜ `match 带前缀: 2026`
- **何时用/不用**：开头格式用 match；任意位置用 search；整串校验用 `fullmatch` 或 `^...$`。
- **锚点**：match 是安检口定点检查（只看队伍开头），search 是全场巡逻找可疑物。
- **易错**：用 `match(r"^\d+$", ...)` 校验没错，但 `match(r"\d+", ...)` 给 "12a" 也过——想校验必须锁尾。
- **关联**：`→ PY-16-11：要全部结果用 findall/finditer`。

### PY-16-11 `findall` vs `finditer`：战利品清单 vs 位置小票
- **是什么**：`findall` 返回全部匹配的字符串列表（带组时返回元组列表）；`finditer` 返回 Match 对象迭代器，每件可查 `group()/span()` 位置。
- **为什么**：只要结果用 findall 最简；要标注"匹配在第几个字符"或取组信息 → finditer 保留完整 Match → 行为：两者都是全部匹配（不止第一处）→ 边界：模式带多个组时 findall 结构变元组，容易懵。
- **怎么写**：
```python
import re
print("findall 只要战利品:", re.findall(r"\d+", "A1 B22 C333"))
for m in re.finditer(r"\d+", "A1 B22 C333"): print("finditer 带位置:", m.group(), "@", m.span())
```
→ 运行输出：`findall 只要战利品: ['1', '22', '333']` ｜ `finditer 带位置: 1 @ (1, 2)` ｜ `finditer 带位置: 22 @ (4, 6)` ｜ `finditer 带位置: 333 @ (8, 11)`
- **何时用/不用**：统计/收集用 findall；要位置、组、上下文用 finditer；只找第一处用 search。
- **锚点**：可疑物全捞出：findall 只交战利品清单，finditer 每件附一张位置小票（span）。
- **易错**：`findall` 带一个组时返回组内容列表而非整匹配；空匹配（如 `a*`）会产出大量空串。
- **关联**：`→ PY-16-10：match/search 只管第一处`；`→ PY-16-07：组影响 findall 返回结构`。

### PY-16-12 `sub` 替换：没收并贴标签 Substitution
- **是什么**：`re.sub(模式, 替换, 文本)` 把所有匹配换成新内容；替换可以是字符串（`\1` 引用组）或函数（按匹配动态算）。
- **为什么**：批量打码、清洗格式、改写模板，字符串 `replace` 写不动"一整类" → sub 按模式换 → 行为：默认全换（count 可限次）→ 边界：替换串里的 `\` 也要防转义（用 `r"..."`）。
- **怎么写**：
```python
import re
print("打码:", re.sub(r"\d{7,}", lambda m: m.group()[:2] + "****", "工号12345678"))
print("反向引用:", re.sub(r"(\w+)@(\w+)", r"\2-\1", "mail me@example"))
```
→ 运行输出：`打码: 工号12****` ｜ `反向引用: mail example-me`
- **何时用/不用**：批量替换/脱敏用 sub；只判断不改文本用 search/findall。
- **锚点**：没收替换：可疑物当场换成"已安检"标签贴回去；函数替换像按件估价再贴不同的签。
- **易错**：`re.sub` 的替换串写 `"\\1"` 与 `r"\1"` 等价，但写 `"\1"` 是控制字符直接出错；忘了原字符串不变（返回新串）。
- **关联**：`→ PY-16-07：反向引用来自分组`。

### PY-16-13 `compile` 与标志位 Flags & Compilation
- **是什么**：`re.compile(模式, 标志)` 把模式编译成可复用对象；常用标志：`re.I` 不分大小写、`re.M` 多行（`^/$` 按行）、`re.S` 让 `.` 吞换行。
- **为什么**：循环里反复用同一模式每次都重新编译浪费 → compile 一次常驻复用 → 行为：标志改变整个模式的匹配规则 → 边界：`re.M` 不影响 `.`，`re.S` 不影响 `^`。
- **怎么写**：
```python
import re
pat = re.compile(r"abc", re.I)          # 预设：不分大小写
print("re.I:", pat.findall("ABC abc Abc")); print("re.M 多行:", re.findall(r"^b\w+", "apple\nbanana", re.M)); print("re.S 让 . 吞换行:", re.findall(r"a.*c", "a\nb\nc", re.S))
```
→ 运行输出：`re.I: ['ABC', 'abc', 'Abc']` ｜ `re.M 多行: ['banana']` ｜ `re.S 让 . 吞换行: ['a\nb\nc']`
- **何时用/不用**：模式用两次以上就 compile；一次性小脚本直接 `re.findall(...)`。
- **锚点**：扫描仪预设程序：compile 把通缉令装订进机器常驻；re.I 是"不分大小写"指示灯，re.M 是"逐行扫描"灯，re.S 是"连缝隙也扫"灯。
- **易错**：`^b\w+` 不加 re.M 只匹配开头（"apple\nbanana" 拿不到 banana）；标志写在 compile 里和函数参数里不能重复叠加出错，混用时看清楚谁生效。
- **关联**：`→ PY-16-02：^/$ 的行为被 re.M 改写`；`→ PY-16-01：re 模块全局函数内部也走编译`。

### PY-16-14 实战：邮箱提取与校验 Email Pattern
- **是什么**：邮箱模式 `[\w.%+-]+@[\w.-]+\.[A-Za-z]{2,}`：本地部分 + `@` + 域名 + 点 + 2 位以上顶级域。
- **为什么**：把邮箱写成 `.+@.+` 会把尾随标点一起吞（"联系 a@b." 连句号都抓）→ 分段加字符类精确圈形 → 边界：这是工程够用版，RFC 全集极复杂别硬抄。
- **怎么写**：
```python
import re
pat = re.compile(r"[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}")
print(pat.findall("联系 bob@example.com 或 alice@test.cn，无效的 a@b 也要过滤")); print("校验:", bool(pat.fullmatch("bob@example.com")), bool(pat.fullmatch("a@b")))
```
→ 运行输出：`['bob@example.com', 'alice@test.cn']` ｜ `校验: True False`
- **何时用/不用**：表单粗校验/日志抽取用它；真注册流程靠发验证邮件，不靠正则。
- **锚点**：扫行李托运条：`@` 前是旅客名条、`@` 后是目的地、最后的点是航段码，缺一段整件扣下（校验 False）。
- **易错**：`a@b` 能过 `.+@.+` 却过不了本模式（缺 `.` 后缀）；中文句号"。"不在类里，混排文本要小心。
- **关联**：`→ PY-16-03：字符类圈定合法字符`；`→ PY-16-10：fullmatch 做整串校验`。

### PY-16-15 实战：手机号校验 Phone Pattern
- **是什么**：大陆手机号模式 `1[3-9]\d{9}`：首位 1、第二位 3-9、共 11 位数字。
- **为什么**：只写 `\d{11}` 会把 20261006123 这类日期串误判为手机号 → 加号段约束"1[3-9]"降低误报 → 边界：新号段持续发放，严苛场景查号段表。
- **怎么写**：
```python
import re
pat = re.compile(r"1[3-9]\d{9}")
for s in ["13812345678", "12812345678", "1381234567", "电话13812345678"]: print(s, "→ 校验:", bool(pat.fullmatch(s)), "| 抽取:", pat.findall(s))
```
→ 运行输出：`13812345678 → 校验: True | 抽取: ['13812345678']` ｜ `12812345678 → 校验: False | 抽取: []` ｜ `1381234567 → 校验: False | 抽取: []` ｜ `电话13812345678 → 校验: False | 抽取: ['13812345678']`
- **何时用/不用**：表单校验用 `fullmatch`；从文本抽取用 `findall`；带国际区号（+86）要另写分支。
- **锚点**：查 11 位号码牌：头两位是号段闸口（1[3-9]），后面 9 位随便过；整牌校验与从人群中捞号码是两种查法。
- **易错**：校验用 `fullmatch`、抽取用 `findall`，同一个模式两种用法结论不同（"电话138..." 校验 False 但抽取得出）；`\d{11}` 对 12 位串用 findall 会误抓其中 11 位。
- **关联**：`→ PY-16-10：fullmatch vs search 的选择`。

### PY-16-16 实战：日期提取 Date Pattern
- **是什么**：兼容三种分隔的日期 `\d{4}[-/.]\d{1,2}[-/.]\d{1,2}`，再用分组拆出年月日。
- **为什么**：日期有 `2026-10-06`/`2026/10/8`/`2026.10.10` 多种写法 → 字符类 `[-/.]` 兼容分隔符 → 行为：分组拿到结构化年月日 → 边界：不校验合法性（2 月 30 日也能过）。
- **怎么写**：
```python
import re
pat = re.compile(r"\d{4}[-/.]\d{1,2}[-/.]\d{1,2}")
print(pat.findall("会议 2026-10-06 开始，2026/10/08 结束，纪念日 2026.10.10")); print("解析成分:", re.match(r"(\d{4})[-/.](\d{1,2})[-/.](\d{1,2})", "2026/10/8").groups())
```
→ 运行输出：`['2026-10-06', '2026/10/08', '2026.10.10']` ｜ `解析成分: ('2026', '10', '8')`
- **何时用/不用**：从文本批量抽日期用它；要判断合法性/算星期交给 datetime（→ PY-14-05）。
- **锚点**：捞日历页：三种撕法（横杠/斜杠/点）都认，捞回来按年/月/日三格归档（分组）。
- **易错**：`[-/.]` 里 `-` 放最前才不当"范围"；模式不锁边界时 "2026-10-061" 也会匹配出 "2026-10-06"。
- **关联**：`→ PY-16-07：分组拆年月日`；`→ PY-14-05：datetime 负责语义校验`。

### PY-16-17 实战：日志字段解析 Log Parsing
- **是什么**：一行日志 `日期 时间 级别 文件:行号 消息`，用命名分组一次拆成字段字典。
- **为什么**：日志按空格 `split` 一改格式就崩（消息里有空格）→ 命名分组按"栏目形状"精确拆 → 行为：`groupdict()` 直接出结构 → 边界：日志格式变了要同步改模式。
- **怎么写**：
```python
import re
pat = re.compile(r"(?P<date>\d{4}-\d{2}-\d{2}) (?P<time>\d{2}:\d{2}:\d{2}) (?P<level>\w+) (?P<file>[\w.]+:\d+) (?P<msg>.+)")
info = pat.match("2026-10-06 09:25:01 ERROR db.py:42 连接超时").groupdict(); print(info["date"], info["level"], info["file"]); print("全部字段:", info)
```
→ 运行输出：`2026-10-06 ERROR db.py:42` ｜ `全部字段: {'date': '2026-10-06', 'time': '09:25:01', 'level': 'ERROR', 'file': 'db.py:42', 'msg': '连接超时'}`
- **何时用/不用**：解析固定格式日志/数据行用命名分组；格式复杂多变上日志解析库（logparser 类）。
- **锚点**：拆安检登记卡：日期栏/时间栏/等级栏/行李号栏/备注栏，按栏目形状一次拆完，卡片变字典。
- **易错**：模式拼接两段时第二段别忘 `r` 前缀；`msg` 用 `.+` 贪婪吞行尾，多字段场景要改 `.+?` 或 `[^,]+` 限定。
- **关联**：`→ PY-16-08：命名分组语法`；`→ PY-15-09：csv 适合表格，正则适合行内字段`。

### PY-16-18 实战：密码校验与前瞻断言 Password Check
- **是什么**：前瞻断言 `(?=...)`：不消耗字符只"探头检查"；`^(?=.*[A-Z])(?=.*\d).{8,}$` 表示"必须含大写、必须含数字、总长 ≥8"。
- **为什么**：多个条件"且"关系，用一个模式串没法顺序表达（先大写后数字？）→ 前瞻像并排的安检通道，各自查一项，全过才放行 → 行为：断言不占匹配内容 → 边界：条件多了可读性差，超过 4 条改用代码逐条判。
- **怎么写**：
```python
import re
pat = re.compile(r"^(?=.*[A-Z])(?=.*\d).{8,}$")   # 大写+数字+至少8位
for pw in ["abc12345", "Abc12345", "Abcdefgh", "Ab1cdefg"]: print(pw, "→", bool(pat.match(pw)))
```
→ 运行输出：`abc12345 → False` ｜ `Abc12345 → True` ｜ `Abcdefgh → False` ｜ `Ab1cdefg → True`
- **何时用/不用**：2~4 个硬条件的校验可用前瞻；业务规则复杂时写普通 if 链更清楚。
- **锚点**：三条并排安检通道：大写灯、数字灯、长度灯，每条通道探头看一眼（`?=` 不抓东西），全亮才放行。
- **易错**：`(?=.*[A-Z])` 里 `.*` 不能跨换行（密码通常单行无妨）；把 `?=` 写成 `(?:...)` 就变成分组消耗字符，语义完全不同。
- **关联**：`→ PY-16-09：多条件"或"用 |，多条件"且"用前瞻`。

## ✅ 自测清单（合上本篇，先写再看）
1. 写模式抽取文本里所有连续数字串，并说出 `match` 与 `search` 谁适合。
> 答案：`re.findall(r"\d+", text)`；找第一处用 `search`，校验开头用 `match`。
2. `<a>1</a><a>2</a>` 用 `<a>.*</a>` 与 `<a>.*?</a>` 各匹配到什么？
> 答案：贪婪一条吃完整串；懒惰两条 `['<a>1</a>', '<a>2</a>']`。
3. `re.findall(r"(\w+)@(\w+)", "a@x")` 返回什么？用命名分组从 "张三-2026" 拆出姓名和年份。
> 答案：`[('a', 'x')]`（带组返回元组）；`re.match(r"(?P<name>\w+)-(?P<y>\d{4})", "张三-2026").groupdict()` → `{'name': '张三', 'y': '2026'}`。
4. `re.match(r"\d+", "12a")` 成功吗？想整串校验怎么写？
> 答案：成功（只匹配前缀 `12`）；改 `re.fullmatch(r"\d+", "12a")` 或加 `$`。
5. 解释 `^(?=.*[A-Z])(?=.*\d).{8,}$` 中 `(?=...)` 的作用。
> 答案：前瞻断言——只探头检查"存在大写/数字"而不消耗字符，最后 `.{8,}` 才是实际匹配内容。
