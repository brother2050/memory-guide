## 一、进料口：参数全家福（口号："对号入座，缺料报错，标签点名"）
### PY-07-01 函数定义与调用 Function Definition & Call
- **是什么**：函数（function）是一段起好名字、可反复执行的工序；`def` 是铺产线，`函数名()` 是按启动钮。
- **为什么**：重复十遍的工序改十处 → 机制：`def` 把代码块登记成一个名字 → 行为：每次调用从头执行、跑完返回调用处 → 边界：只 def 不调用永不开工。
- **怎么写**：
```python
def greet(name):            # 铺产线
    print(f"欢迎{name}进厂")
print(greet("小王"))         # 按启动钮
```
→ 运行输出：欢迎小王进厂 ／ None
- **何时用/不用**：同一逻辑复用 ≥2 次就函数化；只跑一次的三五行脚本直接写。
- **锚点**：铺流水线——def 铺线登记图纸，调用按绿色启动钮；不按按钮传送带纹丝不动。
- **易错**：函数体只写 `print` 却去拿返回值，拿到 None（出料口是空的，见 PY-07-17）。
- **关联**：→ PY-07-18：函数名本身是对象，可赋值、可传递
### PY-07-02 位置参数 Positional Parameter
- **是什么**：按**从左到右顺序**与形参一一对应的实参，不写参数名。
- **为什么**：上料乱序会装错件 → 机制：实参按位置依次绑到形参 → 行为：顺序错不报错但结果错 → 边界：少给一个立刻 TypeError。
- **怎么写**：
```python
def add_material(a, b, c):  # 进料口三个工位
    return a + b + c
print(add_material(1, 2, 3))
add_material(1, 2)          # 少上一袋料
```
→ 运行输出：6 ／ 报错：add_material() missing 1 required positional argument: 'c'
- **何时用/不用**：参数 ≤3 个、含义靠顺序就清楚时用；参数多或同类型易混时改关键字实参（PY-07-05）。
- **锚点**：进料口三个工位按传送带顺序对号入座——先到先放，放错工位机器照跑、产品报废。
- **易错**：`sub(2, 1)` 传反不报错但结果相反；防法是点名传参。
- **关联**：→ PY-07-10：位置参数在签名里必须排最左
### PY-07-03 默认参数 Default Parameter
- **是什么**：形参带默认值（default），调用时不传就用默认。
- **为什么**：多数调用都传同一个值太啰嗦 → 机制：定义时预装一个值、缺位时启用 → 行为：调用处可覆盖 → 边界：默认值在 def 时求值一次，不是每次调用现算。
- **怎么写**：
```python
def stamp(label, times=1):  # 预装压印 1 次
    return label * times
print(stamp("优"), stamp("优", 3))
```
→ 运行输出：优 优优优
- **何时用/不用**：有高频可选配置时用；金额、权限这类必须显式确认的参数别留默认。
- **锚点**：进料口预装的夹具——常规件直接用默认夹具，特殊件来了才换。
- **易错**：默认参数必须排在无默认参数右边，`def f(a=1, b)` 是定义期 SyntaxError。
- **关联**：→ PY-07-04：默认值若是 list/dict 就踩共享陷阱
### PY-07-04 可变默认参数陷阱 Mutable Default Argument
- **是什么**：默认值用 `[]`/`{}` 时，那只"箱子"在 def 时造一次，所有调用共享。
- **为什么**：默认箱子越装越乱 → 机制：默认值存在函数对象 `__defaults__` 里只创建一次 → 行为：多次调用看到同一只箱子、数据残留 → 边界：不可变默认值不受影响。
- **怎么写**：
```python
def add(item, bucket=[]):   # 错：全厂共用一只箱
    bucket.append(item)
    return bucket
print(add("螺丝"))
print(add("螺母"))          # 螺丝还赖着
```
→ 运行输出：['螺丝'] ／ ['螺丝', '螺母']
- **何时用/不用**：永远别拿可变对象当默认值；正解 `bucket=None` 占位、函数内 `if bucket is None: bucket=[]` 现造新箱。
- **锚点**：夹具上粘着上一批的余料——每批料掉进同一夹具越粘越多；None 占位=每次换新夹具。
- **易错**：想当然以为"每次调用都重跑默认值表达式"；写两行测试一跑就现形。
- **关联**：→ PY-07-03：默认参数机制正是本坑的根源
### PY-07-05 关键字实参 Keyword Argument
- **是什么**：调用时写 `参数名=值` 的传参方式，与顺序无关。
- **为什么**：参数一多靠位置传容易装错工位 → 机制：按形参名字绑定 → 行为：可乱序、可跳传 → 边界：名字写错立刻 TypeError，不会静默装错。
- **怎么写**：
```python
def paint(color, area):
    return f"{area}刷{color}"
print(paint("白", "墙面"), paint(area="墙面", color="白"))
```
→ 运行输出：墙面刷白 墙面刷白
- **何时用/不用**：参数 ≥3 个或同类型易混时用；短函数两三个参数，位置传参更紧凑。
- **锚点**：料箱贴标签、按标签点名进料——喊名字（`color=`）而不是排队号。
- **易错**：`colour="白"` 报 unexpected keyword argument；位置实参不能跟在关键字实参后面。
- **关联**：→ PY-07-08：keyword-only 参数只能这样点名进料
### PY-07-06 *args 位置可变参数
- **是什么**：形参前加一个 `*`，把多余的位置实参打包成**元组（tuple）**收进车间。
- **为什么**：进料数量不确定 → 机制：`*` 把剩余位置实参收集为元组 → 行为：0 个也合法，args=() → 边界：`*` 之后的形参只能点名传（PY-07-08）。
- **怎么写**：
```python
def collect(*items):        # 无标签散料箱
    print(type(items).__name__, items)
collect("砂纸", "油漆", "滚筒")
collect()                   # 空箱也合法
```
→ 运行输出：tuple ('砂纸', '油漆', '滚筒') ／ tuple ()
- **何时用/不用**：包装器、工具函数收任意个参数时用；固定签名的业务函数明确列形参更好读。
- **锚点**：`*` 是敞口麻袋——没标签的散料全倒进来，扎口后是一袋（元组）。
- **易错**：args 是元组不可改（`items[0]=…` 报 TypeError）；名字可任意但惯例 `*args`。
- **关联**：→ PY-07-07：**kwargs 收带标签的料
### PY-07-07 **kwargs 关键字可变参数
- **是什么**：形参前加两个 `*`，把多余的关键字实参打包成**字典（dict）**。
- **为什么**：调用方还要塞零散配置项 → 机制：`**` 把关键字实参收集成字典 → 行为：`order(color='白')` 收到 `{'color': '白'}` → 边界：键是合法标识符字符串。
- **怎么写**：
```python
def order(**options):       # 带标签料箱
    print(type(options).__name__, options)
order(color="白", style="简约")
```
→ 运行输出：dict {'color': '白', 'style': '简约'}
- **何时用/不用**：装饰器/包装器透传参数时必备；业务函数滥用会让签名失去约束。
- **锚点**：`**` 是双层标签料箱——每件料都贴名字（键），开箱按标签取件。
- **易错**：`func(**{'a': 1})` 等价 `func(a=1)`；与 *args 并存时散料先入麻袋、标签件后入箱。
- **关联**：→ PY-08-04：装饰器 wrapper 靠 *args/**kwargs 透传任意参数
### PY-07-08 keyword-only 参数 Keyword-Only Argument
- **是什么**：`*`（或已有 `*args`）之后的形参，调用时**必须点名**。
- **为什么**：关键配置怕被按位置误传 → `*` 占掉位置名额、其后只能点名绑定 → 不写参数名直接 TypeError → 可带默认值。
- **怎么写**：
```python
def wire(*, length, color): # 星号后必须点名
    return f"{color}电线{length}米"
print(wire(length=10, color="红"))
wire(10, "红")              # 想按位置塞
```
→ 运行输出：红电线10米 ／ 报错：wire() takes 0 positional arguments but 2 were given
- **何时用/不用**：布尔开关、配置项（如 `*, verbose=False`）强烈建议 keyword-only；教学小例子不必。
- **锚点**：车间门口的点名窗口——`*` 号是窗口，后面的人必须报名字才放行。
- **易错**：`def f(*args, mode)` 里 mode 也是 keyword-only（*args 已占位置名额）。
- **关联**：→ PY-07-10：keyword-only 夹在 *args 与 **kwargs 之间
### PY-07-09 positional-only 参数 Positional-Only Parameter（3.8+）
- **是什么**：`/` 之前的形参**只能按位置**传，禁止点名。
- **为什么**：参数名日后想改又怕破坏调用方 → `/` 划出只认位置的区段 → `cut(size=2)` 报 TypeError → 语法 3.8+ 才支持。
- **怎么写**：
```python
def cut(size, /, material="木板"):  # 斜杠前只认位置
    return f"{material}{size}块"
print(cut(2))
cut(size=2)                 # 想点名
```
→ 运行输出：木板2块 ／ 报错：cut() got some positional-only arguments passed as keyword arguments: 'size'
- **何时用/不用**：写库/公开 API 想保留改名自由时用；日常业务代码少见，能读懂即可。
- **锚点**：传送带直通工位——`/` 是直通闸门，料只能顺带进，不收标签。
- **易错**：`/` 和 `*` 都不是参数名、不占位置，是纯语法记号；3.8 前跑直接 SyntaxError。
- **关联**：→ PY-07-08：与 keyword-only 正好互为镜像
### PY-07-10 参数顺序全家福 Signature Order
- **是什么**：形参表法定次序：位置/默认 → `/` → 位置/默认 → `*args` → keyword-only → `**kwargs`。
- **为什么**：五种参数混排常报 SyntaxError → 解释器按固定次序解析形参表 → 次序对了怎么混都合法 → 违序是定义期报错。
- **怎么写**：
```python
def process(a, b=0, *parts, mode, level=1, **extra):
    return a, b, parts, mode, level, extra
print(process(1, 2, 3, 4, mode="fast", level=2, tag="X"))
```
→ 运行输出：(1, 2, (3, 4), 'fast', 2, {'tag': 'X'})
- **何时用/不用**：写复杂签名前默念"位置→斜杠→散料→点名→标签"；简单函数别堆五种。
- **锚点**：进料总布局图：左门传送带→直通闸→散料口→点名窗→标签仓，单向流动不许逆行。
- **易错**：`f(*lst, **dct)` 的星号是**调用侧解包**，与定义侧的收集星号是反向动作。
- **关联**：→ PY-07-06：*args 在顺序中占"剩余位置"

## 二、车间规矩：作用域与闭包（口号："找工具四级上报"）
### PY-07-11 LEGB 作用域查找规则 Scope Resolution
- **是什么**：名字查找顺序 L→E→G→B：Local 本地 → Enclosing 外层函数 → Global 全局模块 → Builtins 内建。
- **为什么**：同名变量不知道用哪个 → 从最近一层往外找、找到即停 → 内层遮蔽外层同名 → 读外层可以，赋值默认只建本地（见 PY-07-12）。
- **怎么写**：
```python
tool = "厂仓扳手"            # G 全局
def workshop():
    tool = "车间螺丝刀"      # E 外层
    def station():
        print("工位借到:", tool)  # L 没有 → 找 E
    station()
workshop()
print("全局仍是:", tool, "内建可用:", len)
```
→ 运行输出：工位借到: 车间螺丝刀 ／ 全局仍是: 厂仓扳手 内建可用: `<built-in function len>`
- **何时用/不用**：遇 `NameError`/`UnboundLocalError` 先画四级上报图定位；能用参数传就别用全局变量。
- **锚点**：工人找工具四级上报：工位抽屉(L)→车间工具间(E)→厂区总仓(G)→全国统配物资(B)，找到即返回，不翻上级。
- **易错**：函数内对同名变量**赋值**会令它变本地：全局 `x=1` + 函数里 `print(x); x=2` 抛 UnboundLocalError。
- **关联**：→ PY-07-13：闭包 = E 层环境被内层函数带走
### PY-07-12 global 与 nonlocal
- **是什么**：`global` 声明改全局（G 层）名字，`nonlocal` 声明改外层函数（E 层）名字。
- **为什么**：给外层名字赋值会新建一个本地 → 声明后赋值指向指定层 → global 改模块级、nonlocal 改最近外层 → nonlocal 目标必须真存在于外层函数。
- **怎么写**：
```python
count = 0
def inc():
    global count            # 向厂部报账
    count += 1
def make():
    n = 0
    def inner():
        nonlocal n; n += 1; return n   # 向上一道车间报账
    return inner
inc(); f = make()
print("厂部账:", count, "车间账:", f(), f())
```
→ 运行输出：厂部账: 1 车间账: 1 2
- **何时用/不用**：尽量少用 global（多线程、单测都遭罪）；轻量状态用 nonlocal 闭包或类更稳。
- **锚点**：改账必须填调拨单——global 报"厂部"，nonlocal 报"上一道车间"，不报单就只算本工位私账。
- **易错**：`nonlocal` 不能改模块级变量（SyntaxError: no binding for nonlocal），两者不可互换。
- **关联**：→ PY-07-13：闭包计数器必须配 nonlocal 才能改数
### PY-07-13 闭包 Closure
- **是什么**：内层函数引用外层变量、外层函数已返回——函数出厂时带着"出生车间"的环境。
- **为什么**：想让函数记住一点状态又不想用全局/类 → 函数对象持有 `__closure__` 指向定义时的外层变量 → 外层跑完内层仍能读改 → 每次外层调用一套独立环境。
- **怎么写**：
```python
def make_counter():
    n = 0
    def plus():
        nonlocal n; n += 1; return n
    return plus             # 出厂带走工具箱
c1, c2 = make_counter(), make_counter()
print(c1(), c1(), c2())
```
→ 运行输出：1 2 1
- **何时用/不用**：轻量状态、定制回调用闭包；状态复杂、需多方法协作用类（→ 见 [py-09](py-09-oop.md)）。
- **锚点**：工人出厂带走私人工具箱（`__closure__`），箱里的数只有他能改；每招一次工发一只新箱。
- **易错**：循环里 `[lambda: i for i in range(3)]` 是晚绑定，取出来全返回 2；当场定格写 `lambda i=i: i` → [0, 1, 2]（实测）。
- **关联**：→ PY-08-01：装饰器本质就是包着外层环境的闭包

## 三、传送带：递归与 lambda（口号："递归必有收工单，lambda 是临时工"）
### PY-07-14 递归 Recursion
- **是什么**：函数直接或间接调用自身，把大问题拆成同构小问题。
- **为什么**：问题结构自相似（阶乘/树/嵌套）→ 每层调用压栈、触底后逐层结算返回 → 必须有基准情形（收工单）否则跑飞 → 深度受栈上限约束（PY-07-15）。
- **怎么写**：
```python
def fact(n):                # 车间里再开同款车间
    if n <= 1:              # 收工单（递归出口）
        return 1
    return n * fact(n - 1)
print(fact(5))
```
→ 运行输出：120
- **何时用/不用**：树形/嵌套/分治天然递归；简单线性累加用循环更省内存、更好调试。
- **锚点**：车间套车间的套娃工序——每层做一半、剩下交给下一层，最里层贴"收工单"才逐层发货。
- **易错**：出口写成 `if n == 1`（遇 fact(0) 无限递归）；漏写 return 返回 None。
- **关联**：→ PY-07-15：出口缺失的直接后果
### PY-07-15 递归深度与 RecursionError
- **是什么**：每次递归占一层调用栈（call stack），超过上限抛 `RecursionError`。
- **为什么**：递归跑飞会拖垮程序 → 解释器设默认嵌套上限（约 1000）保护调用栈 → 超限抛异常而非死机 → `sys.setrecursionlimit` 可调但治标。
- **怎么写**：
```python
import sys
def deep(n):
    return deep(n + 1)      # 没有收工单
try:
    deep(1)
except RecursionError as e:
    print("报错:", type(e).__name__, "-", e)
print("默认上限:", sys.getrecursionlimit())
```
→ 运行输出：报错: RecursionError - maximum recursion depth exceeded ／ 默认上限: 1000
- **何时用/不用**：能写循环的别为炫技用递归；深嵌套数据（JSON 树）用递归时加深度保护或改迭代。
- **锚点**：厂房限高牌 1000 层——车间嵌套超限楼板塌（栈溢出），限高牌就是 `getrecursionlimit()`。
- **易错**：把上限调到 10 万"解决"溢出，多半换来段错误或更难查的崩溃。
- **关联**：→ PY-07-14：递归必须先写收工单
### PY-07-16 lambda 匿名函数 Lambda Expression
- **是什么**：一行写完的匿名小函数 `lambda 参数: 表达式`，表达式即返回值；最常用岗位是排序键 `key=`。
- **为什么**：为一行逻辑专门 def 太啰嗦 → lambda 是表达式、当场生成函数对象 → 只能含一个表达式、不许语句/return → 逻辑一复杂就难读。
- **怎么写**：
```python
square = lambda x: x * x    # 临时工一行活
parts = [("螺母", 3), ("螺丝", 1)]
print(square(5))
print(sorted(parts, key=lambda p: p[1]))   # 码料员按数量码料
```
→ 运行输出：25 ／ [('螺丝', 1), ('螺母', 3)]
- **何时用/不用**：作 `key=`、filter/map 的一次性小函数用 lambda；多行、要复用、要调试的逻辑写 def。
- **锚点**：临时工——不挂工牌（无函数名）、一行活干完就走；排序 key 是"码料员"岗位，也是临时工（`lambda p: p[1]`）。
- **易错**：`lambda x: return x` 是 SyntaxError（体只能是表达式）；`sorted()` 返回新列表，原地排序用 `list.sort()`。
- **关联**：→ PY-07-18：lambda 生成的也是一台可传递的"机器"

## 四、出料口：返回值与函数对象（口号："出料打包封箱，机器可转让"）
### PY-07-17 return、None 与多返回值 Return Values
- **是什么**：`return` 把结果送出出料口并结束函数；没写 return 返回 `None`；`return a, b` 实为返回元组（tuple），可解包。
- **为什么**：调用了函数却拿不到值 → 机制：无 return 时自动 return None；逗号多个值自动打包元组 → 行为：`a, b = f()` 拆箱，return 后代码不执行 → 边界：超过 3~4 个结果该改命名结构（→ 见 [py-17](py-17-typing-modern.md)）。
- **怎么写**：
```python
def measure(x):
    if x < 0: return None, 0   # 提前收工也照打包
    return x, x * 2         # 出料封箱
print(measure(3), measure(-1))
a, b = measure(4)           # 拆箱
print(a, b)
```
→ 运行输出：(3, 6) (None, 0) ／ 4 8
- **何时用/不用**：要产出值就必须 return；纯副作用（打印/写文件）函数可无 return，但名字要体现动作。
- **锚点**：出料口传送带——return 是往带上放件，不放件出厂箱里是 None；`return a, b` 是两件封成一箱（元组=封箱胶带）。
- **易错**：把 `print(x)` 当 return 是新手第一大坑；解包个数不匹配报 ValueError: too many/not enough values。
- **关联**：→ PY-07-18：返回的箱子和函数都是一等对象
### PY-07-18 函数是一等公民 First-Class Function
- **是什么**：函数名是对象：可赋值、可当参数、可当返回值、可存进容器。
- **为什么**：想把"动作"当材料一样传递（回调/策略）→ 机制：def 把函数对象绑到名字、名字可再绑定 → 行为：`my_func = shout` 后同指一台"机器" → 边界：赋值/传参只是搬运，调用才执行。
- **怎么写**：
```python
def shout(text):
    return text.upper()
my_func = shout             # 贴牌转让
def run(fn, data):          # 函数当进料
    return fn(data)
print(my_func("python"), run(lambda s: s[::-1], "abc"))
```
→ 运行输出：PYTHON cba
- **何时用/不用**：回调、策略选择、map/filter 都靠它；简单直调不必绕一层。
- **锚点**：机器可贴牌转让——流水线是资产：能过户（赋值）、能当料运进别的车间（传参）、能当产品运出（返回）。
- **易错**：写 `run(shout(), data)` 多了括号＝把执行结果当函数传；要运"机器"，不是运"产品"。
- **关联**：→ PY-08-01：装饰器 = 收一台机器、装修后还一台

1. 写 `def join_words(*words, sep="-")`，调用 `join_words("a", "b", "c")` 输出什么？sep 为什么必须点名？
   > 答案：`a-b-c`；sep 在 *words 后是 keyword-only（PY-07-08）。
2. `def f(x, lst=[])` 连续 `f(1)`、`f(2)` 各返回什么？怎么改？
   > 答案：`[1]` 然后 `[1, 2]`（共享默认箱）；改 `lst=None` + 函数内现造列表（PY-07-04）。

   > 答案：None（自动 return None）；元组 `(3, 4)`（PY-07-17）。
