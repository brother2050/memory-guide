## 一、发现的编码系统概览

项目中存在 **4套不同的编码系统**，彼此之间存在大量冲突：

| 系统 | 代表文件 | 说明 |
|------|----------|------|
| **系统A：谐音派PAO** | `01-number/01-number-pao-01.md`、`01-number/01-number-2digit-01.md` | 以谐音为核心的PAO编码，pao-01和2digit高度一致（8处差异） |
| **系统B：核心记忆技巧PAO** | `02-核心记忆技巧.md` §3.3 | 另一套完全不同的PAO编码，以名人为导向 |
| **系统C：混合编码** | `10-combo/*.md` | 混合使用系统A、系统B及自定义编码，来源混乱 |
| **系统D：身份证专用** | `01-number/01-number-idcard-01.md` | 使用第三套编码（如03=济公），与其他系统均不同 |

**独立/不冲突的文件：**
- `02-card/02-card-encoding-02.md`：扑克牌专用编码，文件中已明确声明"与标准00-99数字记忆系统的编码可能不同"
- `04-history/04-history-timeline-01.md`：历史年份编码，使用谐音拆解（如221→鳄衣），非标准PAO
- `06-geography/*.md`：地理数据编码（如960=旧铃铛），用于记忆地理数字，非标准PAO
- `05-chemistry/05-chem-formula-01.md`：化学方程式，无00-99编码定义
- `13-law/13-law-case-01.md`：法律案例，无00-99编码定义

## 五、根因分析

### 5.1 冲突产生的原因

1. **多版本并存**：项目中存在"谐音派"（pao-01）和"名人派"（pao-02/02-核心记忆技巧.md）两套独立设计的编码系统，各有优劣，但未明确指定哪套是标准
2. **combo文件编码来源不明**：10-combo/*.md文件使用了第三套编码（如03=耳朵、09=足球），既不属于谐音派也不属于名人派，来源不可追溯
3. **idcard文件使用独立编码**：01-number-idcard-01.md使用了第四套编码（如03=济公），与其他所有系统不一致
4. **2digit文件未同步更新**：01-number-2digit-01.md与pao-01有8处差异，说明修改pao-01后未同步更新2digit

### 5.2 MEMORY-ENCODING-RULES.md 的权威性问题

MEMORY-ENCODING-RULES.md 定义了编码规则和质量标准，但**未包含完整的00-99编码表**。其示例中使用了 pao-01 的编码（如02=铃儿），暗示 pao-01 是符合规则的标准实现。

规则12明确要求："同一编码在所有文件中必须保持一致"，但目前50+个编码存在冲突，严重违反此规则。

## 六、修复建议

### 6.1 确定权威编码系统

**建议**：以 `01-number/01-number-pao-01.md`（谐音派PAO）为权威标准，原因：
1. pao-01 是最完整、最新的编码表
2. 其编码与 MEMORY-ENCODING-RULES.md 的规则高度一致
3. 谐音派编码反应速度快，适合记忆训练
4. 01-number-2digit-01.md 的谐音编码列与 pao-01 基本一致

### 6.2 修复优先级

| 优先级 | 修复内容 | 涉及文件 |
|--------|---------|----------|
| P0 | 同步 pao-01 和 2digit 的8处差异 | 01-number-2digit-01.md |
| P1 | combo文件统一使用pao-01编码 | 10-combo/*.md |
| P2 | idcard文件统一使用pao-01编码 | 01-number/01-number-idcard-01.md |
| P3 | 02-核心记忆技巧.md 标注为"名人派备选方案" | 02-核心记忆技巧.md |

### 6.3 两套PAO系统的处理方案

pao-01（谐音派）和 02-核心记忆技巧.md（名人派）是**有意设计的两套不同系统**。建议：
- pao-01 作为**标准编码**，所有应用文件统一引用
- 02-核心记忆技巧.md 的PAO表标注为**"名人派备选方案（参考pao-02.md）"**
- 在 MEMORY-ENCODING-RULES.md 中明确指定 pao-01 为权威标准
